Writes the whole file — every record that passes the Read tab's class, return, bounds and crop filters, with every field the format holds; Max points only limits what is read for viewing — as a new LAS or LAZ file, streamed in batches through createLasWriter, then checks the count in the written header. After an edit it writes the edited cloud instead (the points read, so set Max points to 0 to edit every point): the fields read (x y z, class, intensity, return and number of returns, colour); a Split cloud is saved whole, both parts. In Chrome and Edge the file goes straight to disk through the Save dialog, at any size; other browsers build it in memory and download it.

las-laz-js reads and writes ASPRS LAS point clouds in plain JavaScript, with no dependencies, in the browser and Node. LAZ (LASzip) files are read and written too, and point columns can be selected (box, polygon, class, sparse points, outliers), kept, deleted, split, merged, classified, transformed, smoothed (denoised) and registered (to the grid by control points, or to another cloud by picked pairs and ICP), and searched with a voxel neighbour index. The LAZ decoder and encoder are translated from laz-rs (Apache-2.0).

Big files stream through in windows of whole records, never held whole. This page draws with Three.js; the library itself has no dependency.
