## 1. Intent

Raw scanner clouds (a handheld SLAM scan) arrive in the scanner's own frame, near 0,0, with no
CRS (Kirra #131). 0.8.0 puts them on the mine grid, or onto another cloud, and says how well
they fit. Two ways in:
- **Control points from files:** the surveyor's control list (grid) and the scan's target list,
  matched by point name.
- **`alignCloud`:** the user picks the same features on two clouds; the library fits one onto
  the other, then optionally refines with ICP.

Decisions (Brent, 2026-10-23):
- Roadmap: **0.7.1 categorise, 0.8.0 register, 0.9.0 facets, 0.10.0 LOD** (tiled loading of large
  clouds from binary scratch, in memory or a temp disk store). Supersedes the 2026-10-22 order
  (facets 0.8.0, registration 0.9.0).
- Three models: **rigid** (default), **level**, **scale** (§2).
- GCP files are **two lists matched by name**.
- `alignCloud` = **fit from the picks, then optional ICP**.
- The demo's Register tab is a working tool, including picking and naming targets on a cloud in
  GCP mode (Brent: "build the demo so it is functional. It's a good tool").

Success:
- A known transform is recovered from exact pairs to 1e-9, at the origin and at UTM magnitude.
- A bad control point stands out (leave-one-out residuals), even when it drags the fit.
- ICP from three sloppy picks reaches the scan's noise level on a synthetic bench.
- The demo places a real raw scan on the grid and writes it as LAS / LAZ.

## 2. API (`src/register/`)

The result transform is always the 0.5.0 `{ m, t }` (row-major, p' = m·p + t, world to world),
so `transformPoints` and the reader's `transform` option apply it unchanged.

### `fitTransform(from, to, options?)` (`fit.js`)

```js
var f = fitTransform(scanXYZ, gridXYZ, { model: "rigid" });
f.transform;          // { m, t }
f.model;              // "rigid" | "level" | "scale"
f.scale;              // 1 unless model "scale"
f.rotateZ;            // degrees anticlockwise about +Z (model "level" only, else undefined)
f.residuals;          // Float64Array n: |T(from_i) − to_i|
f.dH; f.dZ;           // Float64Array n: horizontal length and signed vertical part of each residual
f.looResiduals;       // Float64Array n: pair i's residual under the fit made WITHOUT pair i
                      //   (NaN when n equals the model's minimum)
f.rms; f.worst;       // RMS of residuals; index of the largest looResidual (residual when n = minimum)
```

- `from`, `to`: flat n×3 arrays (Array, Float64Array or Float32Array), the same length.
- `model`:
  - `"rigid"` (default): rotation + shift, 6 DOF; ≥ 3 pairs not on one line.
  - `"level"`: rotation about Z + shift, 4 DOF; ≥ 2 pairs with distinct XY. For IMU-levelled
    scans.
  - `"scale"`: rigid + one uniform scale (Helmert), 7 DOF; ≥ 3 pairs not on one line.
- `weights` (optional): n non-negative finite numbers, not all zero; a weight of 0 leaves a pair
  out of the fit but its residuals are still reported.
- All sums run in Float64 on offsets from each set's weighted centroid.

### `parseControlPoints(text, options?)` (`controlPoints.js`)

`→ { names: string[], xyz: Float64Array }`
- Delimiter detected per file: comma, tab, semicolon, or runs of spaces. Blank lines and lines
  starting `#` skipped; CRLF accepted; names may be double-quoted (`""` escapes a quote).
- Header optional. A first row whose coordinate fields are not all numbers is a header; its
  names choose columns (case-insensitive): name = `name|id|point|pt|station`;
  x = `x|e|east|easting`; y = `y|n|north|northing`; z = `z|rl|elev|elevation|h|height`.
  No header → `name, x, y, z`.
- `options.columns`: `{ name, x, y, z }` zero-based indices, overriding detection.
- Extra columns ignored.

### `matchControlPoints(scan, grid)` (`controlPoints.js`)

`→ { names, from, to, unmatchedScan, unmatchedGrid }` — pairs in the scan list's order;
`from` / `to` flat Float64Arrays ready for `fitTransform`. Names match exactly after trimming
(case-sensitive: surveyors' `CP1` and `cp1` may differ).

### `alignCloud(moving, fixed, options)` (`align.js`)

```js
var a = alignCloud(scan, reference, {
	pairs: { from: picksOnScan, to: picksOnReference },   // world coordinates, n×3
	model: "rigid",
	movingOrigin: [478000, 6772000, 0], fixedOrigin: [478000, 6772000, 0],
	icp: { maxDistance: 0.5, iterations: 30, sample: 50000, k: 16 },
	onProgress: function (done, total) {}
});
a.transform;   // world -> world
a.fit;         // fitTransform's result for the picks
a.icp;         // { iterations, converged, rmsBefore, rmsAfter, used, sampled } (icp given)
```

- `moving`, `fixed`: point columns (x / y / z or a k = 3 `positions` column), local to their
  origins (default `[0, 0, 0]`); typical Float32 after a `localOrigin` read.
- `pairs` required (≥ the model's minimum). `icp` omitted or `false` = picks only.
- ICP keeps the model: level stays 4 DOF; scale keeps the picks' scale and refines rotation and
  shift.
- `icp.maxDistance` required (same message style as 0.7.0's); `iterations` 30; `sample` 50,000
  (an even `thinSelection` of the moving cloud); `k` 16 (neighbours for each fixed normal).
- `rmsBefore` / `rmsAfter`: point-to-plane RMS over the pairs used, at the picks' transform and
  at the end; `used` / `sampled` = pairs within `maxDistance` with a valid normal / sampled
  points (the overlap).

## 3. Internals

### Rigid and scale: Horn's quaternion method (1987)

Centre both sets on their weighted centroids; cross-covariance S = Σ wᵢ aᵢ bᵢᵀ; the 4 × 4
symmetric N built from S; the rotation is the unit quaternion of N's largest eigenvalue, from a
cyclic Jacobi on the 4 × 4 (the 0.7.0 3 × 3 solver's method, a new 4 × 4 routine in
`src/register/eigen4.js`). Never a reflection. Scale (Umeyama 1991, least squares in the `to`
space): s = Σ wᵢ bᵢ·(R aᵢ) / Σ wᵢ |aᵢ|². t = b̄ − s R ā.

Degenerate: the `from` set's covariance has its middle eigenvalue ≤ 1e-12 of its trace (one
line, or all coincident) → refused.

### Level: exact 2D fit

θ = atan2(Σ wᵢ (aₓbᵧ − aᵧbₓ), Σ wᵢ (aₓbₓ + aᵧbᵧ)) on centred XY; R = rotation by θ about Z;
tₓᵧ = b̄ₓᵧ − R ā; t_z = b̄_z − ā_z. Degenerate: Σ wᵢ (aₓ² + aᵧ²) ≤ 1e-24 · (scale of the set)²
(all pairs at one XY) → refused.

### Leave-one-out

n refits, each without pair i, when n > the model's minimum (a refit that turns degenerate gives
NaN for that pair). Cheap: n is tens.

### ICP (point-to-plane, linearised)

1. Sample the moving cloud (`thinSelection`), to world Float64, then into the fixed cloud's
   local frame (minus `fixedOrigin`) so every sum is near the origin.
2. Build the 0.7.0 k-d tree on the fixed cloud once (about 4.6 bytes a point).
3. Each iteration: apply the current transform to the sample; nearest fixed point within
   `maxDistance` (`kdNearest`, k = 1); its normal from `fitPlane` on its k nearest, **cached per
   fixed point** (normals are only computed where the sample lands, never for the whole fixed
   cloud); drop pairs without a normal.
4. Solve the small-angle system for the increment: rows [(p × n)ᵀ, nᵀ] · [ω; t] = (q − p)·n
   (6 unknowns; level: ω_z, tₓ, tᵧ, t_z), normal equations by Cholesky with a tiny ridge
   (1e-12 · trace). The increment is applied as an exact rotation (Rodrigues of ω), so the
   transform stays orthonormal (times the fixed scale).
5. Stop when the increment's rotation < 1e-7 rad and its shift < 1e-6 · `maxDistance`, or after
   `iterations`; `converged` says which. Fewer than the model's minimum pairs in an iteration →
   stop, keep the last transform, `converged: false`.

`onProgress(done, total)` once per iteration (total = `iterations`), and during the tree build.

## 4. Demo: the Register tab (between Edit and Colour)

The viewer gains a second point layer (the reference, one flat colour) and numbered pick markers;
`viewer.js`, no new dependency.

**Align to a cloud**
- Drop a reference cloud (LAS / LAZ, read in the same Worker as the main cloud, with the same
  `localOrigin`).
- Pick pairs: click a point on the moving cloud, then the same feature on the reference. Each
  click snaps to the nearest drawn point (`viewer.pick`), restricted to the layer being picked.
- Pairs table: #, dH, dZ, 3D, leave-one-out, a delete button; the worst row highlighted.
- Model select, ICP checkbox with max distance, **Fit** (previews the moving cloud in place;
  reports RMS, and ICP's before / after and overlap), **Apply** (commits the transform to the
  cloud the Edit and Write tabs use), **Undo**.

**GCP from files**
- Drop the grid control file; then drop the scan target file, or pick targets on the cloud and
  name them (an inline name field per pick).
- Names matched automatically; unmatched names listed on both sides.
- Same table, Fit, Apply, Undo. (ICP is offered only in Align mode: GCP mode has no reference
  cloud.)

**Output**
- The Write tab writes the aligned cloud (LAS / LAZ).
- **Copy transform** puts `{ m, t }` on the clipboard as JSON (for Kirra, or a later read's
  `transform`).
- Fit and ICP run on the main thread with a progress line, as Denoise does (ICP works on its
  sample, so a 34 M-point cloud stays seconds, plus the tree build).

## 6. Errors

`LasError` `INVALID_ARGUMENT`, the message naming the argument:
- `from` / `to` lengths differ, or not a multiple of 3; a NaN or infinite coordinate (the pair
  number named).
- Too few pairs for the model; degenerate sets (one line for rigid / scale; one XY for level).
- `weights` wrong length, negative, non-finite, or all zero.
- `parseControlPoints`: a row with too few fields (the line number named), a coordinate that is
  not a number, a duplicate name, no rows.
- `alignCloud`: no `pairs`; ICP without `maxDistance`; an origin that is not 3 finite numbers;
  bad `iterations` / `sample` / `k`.
- An ICP overlap below the model's minimum is **not** an error: it stops with
  `converged: false` and the last good transform.

## 7. Testing (oracles, not snapshots)

- **Recovery:** random rotations (all three models), shifts and scales applied to random sets;
  the fit recovers `m` and `t` within 1e-9, at the origin and at UTM magnitude
  (x ≈ 478 000, y ≈ 6 772 000).
- **Noise:** Gaussian noise σ on `to`; RMS within the expected χ range of σ.
- **Optimality:** a numerical minimiser (Nelder–Mead on the model's parameters, from the fit's
  answer perturbed) never finds a lower weighted sum of squares than the closed form.
- **Level:** m₂₀ = m₂₁ = m₀₂ = m₁₂ = 0, m₂₂ = 1; `rotateZ` equals the generating angle.
- **Leave-one-out:** one of 6 pairs moved 0.5 m is `worst`, including a case where its plain
  residual is not the largest.
- **Weights:** a weight-0 pair does not change the fit; doubling all weights changes nothing.
- **ICP:** a synthetic bench (face, crest, toe, floor) with noise, moved by a known small
  transform; three picks with 5 cm errors; ICP recovers the transform to about the noise level;
  60 % overlap still converges; level-mode ICP stays level.
- **Parser / matcher:** each delimiter, with and without a header, E/N/RL and X/Y/Z headers,
  quoted names, blank lines, CRLF, `columns` override; unmatched names on both sides.
- **Real check:** a private raw handheld scan (named by id only) placed by control points; the
  residuals and timings go in the README, as the denoise timings did.
- Coverage: no metric below 0.7.1's numbers.

## 8. Out of scope

Scan-to-surface (mesh) alignment; automatic target detection (spheres, checkerboards);
feature-based global registration (no picks); reprojection between CRSs (callers do it);
non-rigid / affine fits; a Worker for ICP.
