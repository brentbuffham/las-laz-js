- **Status:** agreed in chat 2026-10-23; awaits Brent's review of this written spec
- **Author:** Brent Buffham (https://kirra-design.com), with Claude
- **Library spec:** `2026-10-21-las-laz-js-design.md` · **Builds on:** `2026-10-22-selections-ops-0.5.0-design.md`

## 1. Intent

The Edit tab can already select points (box, polygon, class, return, sparse, outliers). Brent,
2026-10-23: "can we add a categorisation tool? select points and categorise?" — give a selection
a LAS classification, with names for the classes, including the user's own (bench face, crest,
toe, stockpile, equipment) in the LAS user range 64–255, kept in the file so other LAS tools see
them.

Decisions (Brent, 2026-10-23):
- Ships as **0.7.1, before 0.8.0** (registration); independent of it.
- The demo's Categorise tool is a working tool, not a sketch.
- Custom names persist in the LAS **Classification Lookup** VLR.

Success:
- A selection gets a class in one call; points already classified keep their class unless the
  caller asks to overwrite.
- Codes and names round-trip through LAS and LAZ, and are read from other software's files.
- A class code above 31 can no longer be lost silently in point formats 0–5.

## 2. API

### `classifyPoints(cols, selection, code, options?)` (`src/ops/classify.js`)

```js
var r = classifyPoints(pts, sel, 64);                      // only points still 0 or 1 change
var all = classifyPoints(pts, sel, 7, { overwrite: true }); // every selected point changes
r.columns;   // the columns: a new classification array, every other column shared
r.changed;   // how many points changed class (for the message and for undo)
```

- `cols`: point columns with a `classification` column (`Uint8Array`, k = 1).
- `selection`: an ascending `Uint32Array` (0.5.0 rule, checked on use).
- `code`: a whole number 0–255.
- **Existing classes are protected by default** (Brent, 2026-10-23: "if it has a code already
  then … should not overwrite"). Without options, only selected points whose class is 0 (created,
  never classified) or 1 (unclassified) change; a point with any other code keeps it.
- `overwrite` (default false): true changes every selected point, whatever its class.
- `only` (optional): a list of whole numbers 0–255; only selected points whose current class is
  in the list change (e.g. `[7, 18]` to re-class noise). Giving `only` together with
  `overwrite: true` is refused (they contradict).
- `inPlace` (default false): overwrite the input's `classification` array and return the input's
  columns object; without it the result is a copy of the column set (as `transformPoints`) with a
  new `classification` array.
- Returns `{ columns, changed }`. A point already at `code` is not counted as changed.

### `ASPRS_CLASSES` (`src/ops/classify.js`)

A frozen object, code → name, for LAS 1.4 R15 codes 0–22:
0 Created, never classified · 1 Unclassified · 2 Ground · 3 Low vegetation · 4 Medium vegetation ·
5 High vegetation · 6 Building · 7 Low point (noise) · 8 Reserved (model key-point) · 9 Water ·
10 Rail · 11 Road surface · 12 Reserved (overlap) · 13 Wire – guard (shield) · 14 Wire – conductor
(phase) · 15 Transmission tower · 16 Wire-structure connector · 17 Bridge deck · 18 High noise ·
19 Overhead structure · 20 Ignored ground · 21 Snow · 22 Temporal exclusion.
23–63 are reserved; 64–255 are user-definable.

### Class names in files

- **Read:** `openLas` parses a Classification Lookup VLR (user ID `LASF_Spec`, record ID 0) into
  `las.classNames`: `{ [code]: name }`, only the entries the file defines (a non-empty
  description). No VLR → `{}`. A VLR whose length is not a multiple of 16 is `BAD_VLR`.
- **Write:** `writeLas` and `createLasWriter` take `classNames: { [code]: name }` and write the
  VLR: 16-byte entries `{ uint8 ClassNumber; char Description[15] }`, ASCII, NUL-padded, one per
  given code, ascending. Refused: a code outside 0–255 or not whole, a name longer than 15 bytes
  or not printable ASCII.
- Parse / build live in `src/format/ClassLookup.js` (`parseClassLookup`, `buildClassLookup`);
  `parseClassLookup` is exported for callers who walk `las.vlrs` themselves.

### Writer fix: class codes above 31 in point formats 0–5

Formats 0–5 store a class in 5 bits. `encodeRecords` masks with `& 31`, so 64 silently becomes 0.
Now a code above 31 in formats 0–5 is refused: `INVALID_ARGUMENT`, `"point N has class C; point
formats 0-5 hold classes 0-31 — write point format 6 or higher"`. The check runs before any byte
is written (`writeLas`) or per chunk before it is written (`createLasWriter`).

### Colours

`CLASS_COLOURS` gains 19–22. `colourize(..., { by: "classification" })` gives a code with no
entry a stable distinct colour (a hash of the code onto a hue wheel, fixed saturation and
lightness) instead of grey, so user classes are told apart. Codes 0–22 keep their colours.

## 3. Demo (Edit tab, Categorise section)

- A class select: the ASPRS classes, then the file's `classNames`, then classes the user adds.
- **Add class:** a code (64–255, the next free one suggested) and a name (≤ 15 characters, the
  field enforces it).
- **Classify** applies the class to the current selection; points that already have a class
  (anything but 0 / 1) keep it unless **Overwrite existing classes** (unticked by default) is
  ticked. The message says how many points changed and how many kept their class.
- **Undo** restores the previous classification array (one level per Classify, as Denoise's undo).
- After Classify, the view switches to the classification colour mode and a legend lists the
  classes present with their counts and names.
- The Stats tab's class table shows names.
- The Write tab writes the names (`classNames`); for point formats 0–5 with a class above 31 it
  shows the writer's message and suggests format 6 (or 7 / 8 to keep RGB).
- The classification field is read by default (`DEFAULT_FIELDS`), so no read option changes.

## 5. Testing (oracles, not snapshots)

- `classifyPoints`: random clouds (classes drawn from 0–255) and selections; the result equals a
  brute-force loop for the default (only 0 / 1 change), `overwrite: true` and `only`; a selected
  point at class 2 is unchanged by default; `changed` equals the brute count; copy vs `inPlace` (input untouched / same array);
  an empty selection changes nothing.
- Lookup VLR: bytes built by hand from the LAS 1.4 R15 table layout equal `buildClassLookup`'s;
  parse(build(x)) = x; a 15-character name fits, 16 is refused; NUL-padding read back trimmed.
- Round trip: write LAS and LAZ (formats 1, 3, 6, 7) with names and user codes; read back the same
  codes per point and the same `classNames`.
- Refusal: format 3 with a class 64 point → the message names the point; nothing written.
- Colours: 0–22 unchanged; two different unknown codes give different colours; the same code
  always the same colour.
- Coverage: no metric below the 0.7.0 numbers.

## 6. Errors

`INVALID_ARGUMENT` naming the argument: `code` / `only` entries not whole numbers 0–255; no
`classification` column; a bad selection (0.5.0 messages); `classNames` code or name invalid;
class above 31 in formats 0–5. `BAD_VLR` for a malformed lookup VLR.

## 7. Out of scope

Automatic classification (ground filters, CSF, PMF); classification flags (synthetic,
key-point, withheld, overlap) — readable already, not set by `classifyPoints`; per-class
visibility in the demo beyond the legend.
