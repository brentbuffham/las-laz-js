# las-laz-js 0.9.0 — Facets and joint sets — Design Spec

- **Status:** API, demo, errors and testing agreed in chat 2026-10-23; awaits Brent's review of
  this written spec
- **Author:** Brent Buffham (https://kirra-design.com), with Claude
- **Library spec:** `2026-10-21-las-laz-js-design.md` · **Builds on:** 0.7.0 k-d tree, normals and
  noise (`2026-10-22-denoise-0.7.0-design.md`)

## 1. Intent

Kirra #127: find the joint sets in a high-detail pit-wall scan. 0.9.0 splits the scan into
**facets** (flat patches: plane, dip / dip direction, area, outline) and groups them into
**joint sets** (families by orientation, with Fisher statistics), as CloudCompare's Facets tool
does, with zero dependencies. Kirra draws the stereonet, exports the CSV and hands the sets to
the wall damage ribbon as weak planes; las-laz-js returns the numbers, the per-point tags and the
outlines.

Decisions (Brent, 2026-10-23):
- **Region growing on point normals** (approach A of three; the others were CloudCompare's k-d
  tree cells and voxel planes): best facet edges, reuses 0.7.0. The growth test is the same two
  checks as trimesh-build-js's bridging guard — normals agree, the point lies near the plane.
  trimesh-build-js already builds on las-laz-js's k-d tree, so nothing is imported from it.
- **Joint sets automatic, with overrides:** density peaks of the area-weighted poles, or a fixed
  count, or the user's own set windows.
- **Extra bytes are 0.9.1**, not 0.9.0: per-point facet / set numbers live in memory in 0.9.0;
  reading and writing the LAS 1.4 Extra Bytes VLR (LAS and LAZ, for any file, not only facets)
  is its own release.
- The demo gets a Facets tab, including its own SVG stereonet (Kirra keeps its own).

Success:
- Synthetic walls of known planes come back plane for plane: normals within 1°, dip / dip
  direction within 0.5°, at least 95% of each plane's points, area within 5%.
- Joint sets from Fisher-distributed poles come back: means within 2°, K within 25%.
- A real wall scan gives sets that look right on the demo's stereonet.

## 2. API (`src/facets/`)

### Orientation convention (Kirra)

A plane's **pole** is its unit normal oriented up (z > 0; a vertical one by 0.7.0's
`orientNormal` rule: x > 0, then y > 0). **dip** = acos(n_z) in degrees, 0–90 (90 vertical).
**dipDirection** = the bearing of the pole's horizontal part, degrees clockwise from north
(+Y), east (+X) = 90: `(atan2(n_x, n_y) · 180/π + 360) % 360`; 0 when dip is 0. Coordinates are
x east, y north, z up.

### `findFacets(cols, options)` (`findFacets.js`)

```js
var f = findFacets(pts, { maxDistance: 0.3, maxAngle: 10, minArea: 1 });
f.facet;    // Uint32Array, one per point: its facet (1 … n), 0 = none
f.facets;   // [{ id, count, normal: [x, y, z], centroid: [x, y, z], dip, dipDirection,
            //    area, rms, outline: Float64Array }]  — ids 1 … n by area, largest first
f.planeDistance;   // the plane distance used (given or 3 x the measured noise)
```

- `cols`: point columns (x / y / z or a k = 3 `positions` column), in any frame (local Float32
  about a `localOrigin`, or Float64 world); every result is in the columns' own frame.
- `maxDistance` (required): the neighbourhood, as 0.7.0 (normals, and growth to the k nearest
  within it).
- `k` (default 16): neighbours, as 0.7.0.
- `maxAngle` (default 10): a neighbour joins only if its normal is within this many degrees of
  the facet's (an axial test: |n · m| ≥ cos).
- `planeDistance` (default 3 × `estimateNoise`, or `maxDistance` / 10 when the noise cannot be
  measured): a neighbour joins only if it lies within this distance of the facet's plane.
- `minArea` (default 1, square units of the columns) and `minPoints` (default 20): smaller
  facets are dropped; their points go back to 0.
- `outlineCell` (default 2 × the facet's median nearest-neighbour spacing): the in-plane grid's
  cell size for `area` and `outline`.
- `normals` (optional): `{ normal, residual }` from `pointNormals` with the same `k` and
  `maxDistance`, so a second run with other tolerances skips the normals.
- `onProgress(done, total)`: over the normals and then the growth.
- `area`: the in-plane grid's filled cells × cell² (independent of point density).
- `outline`: the outer edge of the largest 4-connected patch of filled cells, a closed polygon on
  the facet's plane (x, y, z per vertex, not repeated at the end), anticlockwise seen from the
  side the pole points to; collinear vertices removed.
- `rms`: the facet's points' RMS distance from its plane.

### `jointSets(facets, options?)` (`jointSets.js`)

```js
var j = jointSets(f.facets);                                       // automatic, maxAngle 15
var j2 = jointSets(f.facets, { count: 3 });
var j3 = jointSets(f.facets, { windows: [{ dip: 72, dipDirection: 135, angle: 12 }] });
j.family;      // Uint32Array, per facet (by its position in facets): its set (1 … m), 0 = none
j.families;    // [{ id, normal, dip, dipDirection, fisherK, cone95, facets, area }] — by area
j.pointFamily(f.facet);   // Uint32Array per point: its facet's set (0 for none)
```

- **Automatic** (default): mean-shift on the sphere over the facets' poles, axial (a pole and
  its opposite are one), weighted by area, window `maxAngle` (default 15°); modes within
  `maxAngle` / 2 merge; a mode is a set when it gathers at least `minFacets` (default 3) facets.
  Each facet joins the nearest set within `maxAngle`, else 0.
- `count`: the `count` largest modes (fewer if fewer are found), refined by spherical k-means;
  every facet joins its nearest set.
- `windows`: the user's sets, `{ dip, dipDirection, angle }` each; a facet joins the window
  nearest its pole among those within their `angle`, else 0. No automatic search.
- **Per set**, from its facets (poles flipped into the mean's hemisphere, weights w_i = area_i
  scaled so Σ w_i = N, the facet count): mean pole = normalised Σ w_i p_i; R = |Σ w_i p_i|;
  `fisherK` = (N − 1) / (N − R); `cone95` = acos(1 − (N − R) / R · (20^(1/(N − 1)) − 1)) in
  degrees; both NaN for N < 2. `facets` = N; `area` = Σ area.

## 3. Internals

### Growing facets

1. Normals and residuals (given, or `pointNormals`); the k-d tree (0.7.0) built once.
2. Seeds: the points with a normal, by residual, flattest first.
3. From each seed not yet in a facet: a queue; each popped point's k nearest within
   `maxDistance` (`kdNearest`) join if not in a facet, normal within `maxAngle` of the facet's,
   and within `planeDistance` of its plane. The plane comes from running Float64 sums (on
   offsets from the seed) and is refitted (0.7.0's `smallestEigen`, the 3 × 3 Jacobi in
   `ops/normals.js`, already exported internally) when the facet's count
   passes 1.25 × the count at the last fit, so the work stays linear.
4. A finished facet below `minPoints`, or whose final `area` is below `minArea`, is released:
   its points go back to 0 and may join later facets (they are not seeds again).
5. Final plane per facet from its points; `rms`, centroid, orientation; ids renumbered by area.

### Area and outline

Project the facet's points onto its plane (an orthonormal basis u, v); a grid of `outlineCell`;
`area` = filled cells × cell²; the outline traces the boundary edges of the largest
4-connected component of filled cells (holes inside it are not traced), joins them into one
ring, drops collinear vertices, and maps back to 3D on the plane (centroid + a·u + b·v).

### Joint sets

Mean-shift per seed (every facet pole, or an even 2,000 of them when there are more):
m ← normalise(Σ_{|p_j·m| ≥ cos θ} w_j · sign(p_j · m) · p_j) until it moves less than 1e-6 rad
(at most 50 steps). Modes are merged, ranked by the area they gather; assignment and statistics
as §2.

## 4. Demo: the Facets tab (after Register)

- **Run** on the current selection if there is one (a polygon round the wall), else the whole
  cloud; settings: max distance, max angle, plane distance (blank = measured), min area;
  **Find facets**, with progress; the status gives facets, points in facets and time.
- **Colour by** Facet (each its own colour) and Joint set (each set its colour, none grey), on
  the Colour tab too.
- **Outlines** drawn on the cloud (viewer line loops), with a Show outlines checkbox.
- **Joint sets:** Automatic (max angle) / Count (N) / Windows (typed `dip/dipdir/angle; …`);
  a table per set: colour, dip / dip direction, Fisher K, 95% cone, facets, area; **Select set**
  makes the set's points the selection (to Classify, delete, crop).
- **Stereonet:** a lower-hemisphere equal-area (Schmidt) net in SVG: each facet's pole (dot by
  area, colour by set), each set's mean and its 95% cone, N / E / S / W ticks.
- **Hover** adds the point's facet, dip / dip direction and set.
- **Export:** Download facets CSV (id, centroid, dip, dip direction, area, rms, set, points) and
  sets CSV.
- The side panel is 400–520 px wide with wrapping tabs (cedfb00), so the ninth tab fits.

## 6. Speed and memory

About twice `pointNormals`: roughly 10 s a million points in Node (normals ~4.6 s, growth one
k-nearest query a point), so a 5 M-point wall region about 50 s. Memory beyond the columns:
the k-d tree (~4.6 bytes a point), normals and residuals (16), the facet column (4), flags and
the queue (~5): about 30 bytes a point.

## 7. Errors

`INVALID_ARGUMENT`, naming the argument: `maxDistance` missing or not positive; `maxAngle` not
in (0, 90); `planeDistance` not positive; `minArea` negative; `k` or `minPoints` not a whole
number ≥ 3; `outlineCell` not positive; `normals` not `{ normal (3 a point), residual (1 a
point) }` for this cloud; `jointSets`: `facets` not a facet list, `count` and `windows` both
given, `count` not a whole number ≥ 1, a window's dip outside 0–90, dip direction outside 0–360
or angle outside (0, 90], `maxAngle` not in (0, 90). No facets (an empty cloud, all noise, a
line of points) is not an error: `facets` is empty and every point 0; `jointSets` of no facets
is no sets.

## 8. Testing (oracles, not snapshots)

- **Known planes:** synthetic walls of 3 joint sets, several planes each, dips and dip
  directions set by construction, 5 mm noise and 1% stray points: each plane one facet, normal
  within 1°, dip / dip direction within 0.5°, ≥ 95% of its points, area within 5%.
- **Convention:** a plane dipping 30° east → dip 30, dip direction 90; toward north → 0; a
  vertical facet facing east → dip 90, dip direction 90 by the rule of §2.
- **Edges:** two planes meeting at a crest → two facets split at the crest; two parallel planes
  0.5 m apart (a step) → two facets.
- **Hard inputs:** exact duplicate points, a line of points (a scanned blasthole), a cloud
  sparser than `maxDistance` → no crash, no NaN; UTM magnitude gives the same facets as the
  origin.
- **Outline:** a 10 × 10 m plane → closed, on the plane (1e-9), anticlockwise seen from the pole,
  area within 3%.
- **Joint sets:** poles from 3 Fisher distributions (K 50–200) → automatic finds 3, means within
  2°, K within 25%; Fisher K and cone95 equal hand-computed values; `count`, `windows`; a pole
  and its opposite in one set; area weighting changes the mean as it should.
- **Speed:** 1 M points timed (not under coverage).
- **Real check:** a private wall scan (named by id only): sets reported; a comparison with
  hand-mapped or Compass planes when Brent has them.
- **Demo:** a browser check of the Facets tab.
- Coverage: no metric below 0.8.0's numbers.

## 9. Out of scope

Extra bytes (0.9.1); facets of a file larger than memory (streamed, tile by tile); curved
features; meshing (trimesh-boolean / trimesh-build-js); Kirra's stereonet, CSV export and the
weak-plane hand-off.
