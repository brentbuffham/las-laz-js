- **Author:** Brent Buffham (https://kirra-design.com), with Claude

## 1. Intent

Handheld SLAM pit scans are fuzzy. A flat bench reads as a band a few centimetres thick, so
Kirra's surfaces of them are spiky. Brent asked for a tool that "can denoise the point cloud …
like sound equipment has a denoising effect", acting on the cloud itself, not its triangulation.
An FFT needs a regular grid, which a scan is not. The point-cloud equivalent is
smoothing each point against its neighbours. 0.7.0 adds that, plus the stray-point filter
deferred from 0.6.0, on the 0.6.0 voxel index, with zero dependencies.

Decisions (Brent, 2026-10-22):
- The noise is **both** surface fuzz and stray points. There are two tools: `selectOutliers`
  for strays (a selection for `removePoints`, like `selectSparse`) and `denoisePoints` for fuzz
  (moves points).
- **Both smoothing methods** live in one tool: `"bilateral"` (the default; crests and toes stay
  sharp) and `"mls"` (a plane fit; it smooths more and rounds edges slightly).
- Neighbours are **the k nearest, capped by `maxDistance`** (option 3 of 3; a fixed radius
  is slow near the walk path and unstable far from it, and pure k-nearest can reach across a pit).
  `nearestPoints` becomes a public query.
- **In memory**, like `selectSparse`; the streamed whole-file version is later.
- Roadmap: **0.7.0 denoise, 0.8.0 facets (with outline polygons), 0.9.0 registration**.
  Facets reuse `pointNormals` and its `residual`.

Success:
- On a flat bench, scatter about the plane drops several-fold (e.g. 2–3 cm to under 1 cm).
- A crest stays sharp; holes and cones keep their shape.
- Stray-point removal matches PDAL's statistical outlier filter point for point.

## 2. API

Point columns in memory: `x` / `y` / `z`, or a k = 3 `positions` column (Kirra's layout), as
`buildIndex` takes them. Arithmetic is Float64 throughout. Ties between equal distances go to
the lowest point number, so every result is deterministic. "Neighbours" of a point are the
other points among its k nearest that lie within `maxDistance` (inclusive).

### k-nearest query (`src/index/knn.js`)
- `nearestPoints(index, [x, y, z], k, { maxDistance, xy })` → `{ points: Uint32Array, d: Float64Array }`.
  Up to k points, nearest first, with their distances. `k` is required, a whole number ≥ 1;
  more than the point count returns every point. `maxDistance` is optional (default unlimited).
  `xy: true` measures in plan. The result is in distance order, so it is not a selection
  (as `pointsNearRay`'s `{ points, t, d }`). An empty index returns empty arrays.
- Internally, a version for point i that skips i itself ("k nearest other points").

### Stray points (`src/ops/outliers.js`)
- `selectOutliers(cols, { k = 8, multiplier = 2, onProgress })` → selection for `removePoints`.
  PDAL's `filters.outlier` `method=statistical` with its defaults (`mean_k` 8, `multiplier` 2):
  each point's mean distance to its k nearest other points; the mean μ and the sample standard
  deviation σ (n − 1) of those means; a point is selected when its mean > μ + multiplier · σ.
  There is no `maxDistance`, as in PDAL. A cloud of k points or fewer selects nothing.

### Normals (`src/ops/normals.js`)
- `pointNormals(cols, { k = 16, maxDistance, onProgress })` → `{ normal: Float32Array (3 per point), residual: Float32Array }`.
  `normal` is the unit normal of the plane fitted to the point and its neighbours. It points
  upward (z > 0), and a horizontal normal takes the sign that makes its first non-zero
  component positive. `residual` is the RMS distance of those points from the plane: the local
  noise. Fewer than 3 neighbours → normal (0, 0, 0), residual NaN.
- `estimateNoise(cols, { k = 16, maxDistance })` → a number: the median finite `residual` over up
  to 100,000 points spread evenly through the cloud (`thinSelection`'s rule); NaN when there is
  none. Kirra shows it ("noise measured: 2.1 cm") and pre-fills the smoothing's noise field.

### Smoothing (`src/ops/denoise.js`)
- `denoisePoints(cols, { method = "bilateral", k = 16, maxDistance, sigma, iterations = 1, normals = false, inPlace = false, onProgress })`
  → point columns, as `transformPoints` returns them: new x, y, z (or `positions`) of the
  input's types, every other column shared. `inPlace` overwrites the input's coordinates once
  every point has been computed. `normals: true` adds a `normal` column (Float32, k = 3), the
  normals fitted in the last pass.
- `sigma` is the noise level in metres (a standard deviation). Omitted → `estimateNoise` with
  the same `k` and `maxDistance`. If the measured noise is 0 or NaN (a perfectly flat or a
  very sparse cloud), nothing moves.
- A point with fewer than 5 neighbours does not move.
- Order of use in Kirra: `selectOutliers` → `removePoints` → `denoisePoints` (strays go first so
  they cannot pull the surface).

`maxDistance` is **required** for `pointNormals`, `estimateNoise` and `denoisePoints`, as
`radius` is for `selectSparse`. The reach depends on the scanner and the range, and a wrong default
would reach across a crest. The message suggests a value ("e.g. 0.3 m for a handheld scan").

## 3. Internals

### `nearestPoints`
Chebyshev rings of cells outward from the query's cell (whole Z columns with `xy`), keeping the
best k in a bounded max-heap ordered by (distance², point number). Stop when the heap is full
and the next ring's inner distance exceeds the k-th distance, or the rings pass `maxDistance`
or the grid's edge. `nearestPoint`'s tightened off-edge bound and its fall-back scan carry over,
so a query far off the cloud stays fast.

### The working index
Each of `selectOutliers`, `pointNormals`, `estimateNoise` and `denoisePoints` builds a private
index sized for k-nearest queries. The 0.6.0 automatic cell size aims at 16 points per cell of
the bounding *volume*, so it is coarse on a surface. Instead, a coarse automatic index answers
k-nearest queries for 1,000 points spread through the cloud, and the working index's cell size is the
median distance to their k-th neighbour (at most `maxDistance` when one is given). A 3 × 3 × 3
block then holds about k points on a surface.

### Plane fit
The covariance of the point and its neighbours (about their centroid, weighted where a
method says so); the normal is the eigenvector of the smallest eigenvalue, from a cyclic Jacobi
solver on the 3 × 3 matrix (exact enough, and steady when two eigenvalues are equal, as on a
line of points). `residual` = sqrt(smallest eigenvalue / total weight).

### `"bilateral"` (Fleishman, Drori and Cohen-Or, 2003, applied to points)
For point p with normal n, each neighbour q has distance t = |q − p| and height h = n · (q − p).
Weights: a distance term exp(−t² / 2σc²) with σc half the distance to p's k-th neighbour (it
adapts to density), times a height term exp(−h² / 2σs²) with σs = 2 · sigma. Points on p's own
face (h within a couple of sigma) count; a face across a crest, 10–20 cm off p's plane,
counts for almost nothing. That is what keeps edges sharp.
1. Fit the plane to p and its neighbours (unweighted) → n₀.
2. Refit with both weights, heights measured on n₀ → n. A crest point's plain fit averages
   its two faces; the refit follows the face the point is on.
3. Move along n: p′ = p + n · Σ w h / Σ w over the neighbours (heights on n).

### `"mls"`
Fit a plane with the distance weights only (weighted centroid c, normal n), and move p onto
it: p′ = p − n · (n · (p − c)). On curved ground (cones, hole collars), a 10 cm neighbourhood
introduces about 1 mm of bias.

### Passes
Each pass reads the old coordinates and writes the new ones into a separate buffer, so
results do not depend on point order. Pass 2 onwards rebuilds the working index on the moved
points. Sums run over neighbours nearest first, so the floating-point results are repeatable.

## 5. Speed and memory

Each point costs one k-nearest query plus one or two 3 × 3 fits. The estimate is a few
microseconds a point on one thread: about 5 s for 1 M points and minutes for a 34 M-point scan. The
bench measures `denoisePoints` on s4 (1 M) and s6 (34 M), and on the 160 M scan when memory
allows. The README states the measured figures.
- Single-threaded in 0.7.0. Kirra runs the calls in a worker, posting `onProgress(done, total)`
  to its UI (about every 1 % of the points). A worker running synchronous code cannot be told
  to stop part way, so there is no abort: Kirra cancels by terminating the worker. Splitting the work over
  the worker pool (tiles with a neighbour margin) is a later release, once the single-thread
  numbers are known.
- Memory beyond the input: the working index (about 8 bytes a point), the output coordinates
  (12 bytes a point Float32, 24 Float64; with `inPlace`, a pass buffer of that size, copied back
  at the end), `normal` 12 bytes a point when asked for. `selectOutliers` holds one Float64 mean a point (exact
  thresholds, as PDAL's doubles). Nothing holds a per-point neighbour list.

## 6. Testing (oracles, not snapshots)

- **`nearestPoints`**: brute force over the 0.6.0 sweep (uniform, clustered, plane; Float32 /
  Float64; x / y / z and `positions`; cell sizes far below and above the query scale; inside and
  outside the grid; k 1, 5, 50, more than the count; with and without `maxDistance`; `xy`):
  same points, same order, same `d`, same tie-breaks. Off-edge query speed as `nearestPoint`'s.
- **`selectOutliers`**: a brute-force JS oracle (all-pairs distances) on small clouds;
  hand-worked: one far point flagged, a uniform grid flags none, k ≥ count flags none, duplicates.
  **PDAL oracle** (dev machine, `LAS_PDAL`): `filters.outlier method=statistical mean_k=8
  multiplier=2` flags the same points on fixture clouds and sample crops.
- **`pointNormals`**: noise-free planes at many tilts (horizontal, 45°, vertical) give their exact
  normal within 1e-9 and residual within 1e-9 of 0, with the sign rule; Gaussian noise σ gives
  a median residual within 10 % of σ; fewer than 3 neighbours → zero normal, NaN residual;
  collinear points give a deterministic normal.
- **`denoisePoints`** on synthetic surfaces with a known true shape and seeded Gaussian noise
  (σ 2 cm, `maxDistance` 0.3):
  - plane: RMS distance to the true plane drops at least 3 times (bilateral) and 4 times (mls);
  - crest (two planes meeting at 90°, a bench edge): within 10 cm of the edge, bilateral's
    mean error from the true surface is at most half of mls's;
  - cone (a blasthole collar): mean radial error drops, and the apex height moves less than σ;
  - shuffling the point order permutes the output exactly; `positions` equals x / y / z;
    Float32 input gives Float32 output; `inPlace` equals the copy; points with fewer than 5
    neighbours unmoved; `sigma` 0 or NaN noise moves nothing; `iterations` 2 smooths more than 1.
  The plan pins exact thresholds once measured; these are the floors.
- **Private sample** (existing mechanism, no file names committed): a crop of Brent's handheld pit scan —
  median residual before and after, and the bench.
- Errors: each `INVALID_ARGUMENT` message names its argument.
- Coverage: no metric below the 0.6.2 values.

## 7. Demo

Edit tab, a **Denoise** section:
- **Outliers**: k (8) and multiplier (2), "Select outliers". The points turn red with their
  count, and the existing Delete / Keep / Split act on them.
- **Smooth**: method (bilateral / mls), k (16), max distance (0.3), noise (blank = measured;
  "Measure" fills it), iterations (1), "Smooth", and "Undo smooth" (keeps the coordinates from
  before, to compare). It acts on every point read, like the edits. The drawn spread
  (0.6.1) is redrawn from the moved points.
- A **Roughness** colour mode (residual, on the ramp) shows where the fuzz is, before and
  after.

## 8. Errors

`LasError` `INVALID_ARGUMENT`, naming the argument: `k` not a whole number ≥ 1; `multiplier`
not finite; `maxDistance` missing (where required) or not a positive finite number; `sigma`
not a positive finite number; `method` not `"bilateral"` or `"mls"`; `iterations` not a whole
number ≥ 1; `onProgress` not a function; a query point not 3 finite numbers (2 with `xy`); an index
that is not self-consistent. A NaN or infinite coordinate is refused by the index (naming the
point). `TOO_MANY_POINTS` above 4,294,967,295 points.

## 9. Out of scope

Facets and joint sets (0.8.0); registration (0.9.0); the streamed whole-file versions (0.6.x
onwards); splitting the work over the worker pool; abort; FFT / graph-spectral (Taubin)
smoothing, which rounds edges; polynomial (second-order) MLS; normals oriented to a scanner
trajectory; smoothing only in Z (a 2.5D shortcut that bends walls).
