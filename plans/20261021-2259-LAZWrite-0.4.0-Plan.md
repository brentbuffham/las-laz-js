# Write LAZ (0.4.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `writeLas` / `createLasWriter` write LAZ (`compress: true`) for point formats 0–3 and 6–8, byte-identical to PDAL 2.10 (LAZperf) on the fixtures.

**Architecture:** Writing mirrors reading: `encodeRecords` makes raw LAS records; a chunk compressor (mirror of `createChunkDecoder`) turns each chunk of records into LAZ bytes. Each item compressor sits beside its decompressor and shares its models and tables. Chunks compress independently, so the 0.3.0 worker pool gains a `compress` task.

**Tech Stack:** Vanilla JavaScript ES modules, `node --test`. Port source: laz-rs (https://github.com/laz-rs/laz-rs) — the same files the decoders name in their headers (`src/encoders.rs`, `src/compressors.rs`, `src/las/point0.rs` v2, `src/las/gps.rs` v2, `src/las/rgb.rs` v2 + v3, `src/las/extra_bytes.rs` v2 + v3, `src/las/nir.rs` v3, `src/las/point6.rs` v3_v4, `src/record.rs`, `src/laszip/chunk_table.rs`, `src/laszip/vlr.rs`) — the *compressor* halves.

**Spec:** `docs/design/2026-10-21-laz-write-0.4.0-design.md`

## Global Constraints

- Zero dependencies, no WASM; ES modules; browser and Node ≥ 22. Nothing new in `package.json` but the version.
- PDAL is a development-machine oracle only, opt-in through `LAS_PDAL=<path to pdal>`; tests skip (loudly) without it.
- House style: `var`, constructor functions + prototypes, tabs, the `//====` file header block. Every ported file carries the Apache-2.0 header naming laz-rs / LASzip and the change made, as the decoders do (`NOTICE` already covers them).
- Source guards (`test/guards.test.js`) hold: no `<<`, `>>`, `>>>`, `| 0` on a line naming a position / count / size / offset / start / end / first / len / length / at, unless the line is a byte mask marked `// bits-ok`; no static `node:` import in `src/`; nothing in `src/` imports from `test/`.
- LASzip VLR: compressor 2 (formats 0–3) or 3 (6–8), coder 0, version **3.4 r3**, options 0, chunk size (default **50000**), special EVLRs count −1 and offset −1, then items (spec §4 table). Chunk table version **0**, fixed-size chunks only.
- Items: formats 0–3 → Point10 6/20/v2, GpsTime11 7/8/v2, RGB12 8/6/v2, extra bytes Byte 0/n/v2. Formats 6–8 → Point14 10/30/v3, RGB14 11/6/v3, RGBNIR14 12/8/v3, extra bytes Byte14 14/n/v3. Extra-byte count n = `recordLength − POINT_FORMATS[fmt].size`.
- `compress` with formats 4, 5, 9, 10 → `LasError` `UNSUPPORTED`; `chunkSize` not a whole number ≥ 1 → `INVALID_ARGUMENT`.
- Coverage thresholds unchanged (`npm run test:coverage`); the already-failing function gate (browser-only code) is not this release's to fix, but no metric may drop below its 0.3.1 value (lines 99.40, branches 93.42, functions 96.47).

## Review Focus

- A 1.4 cloud where a field never changes in a chunk (constant intensity, class, GPS time): its layer is written empty (size 0); PDAL and our reader must still decode it → Task 5 test "constant fields leave empty layers that decode".
- Several scanner channels interleaved in format 6: Point14 switches context per channel → Task 5 test "scanner channels 0-3 interleaved round trip".
- `writePoints` called several times without awaiting (the LAS writer allows it): chunks must keep input order → Task 4 test "unawaited writePoints calls keep their order".
- Extreme coordinate jumps (X from −2³¹ to 2³¹−1 between points, Z alternating extremes): the integer compressor's corrector wraps → Task 2 and Task 5 tests "extreme deltas round trip".
- A pool that cannot start during a compressed write: output on this thread, byte-identical → Task 6 test "no workers: same bytes on this thread".
