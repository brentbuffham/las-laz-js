# Register 0.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `fitTransform` (rigid, level, scale) with leave-one-out residuals, `parseControlPoints` / `matchControlPoints` for control files matched by name, and `alignCloud` (fit from picked pairs, then optional point-to-plane ICP); the demo gains a working Register tab (Align to a cloud; GCP from files or picked, named targets).

**Architecture:** `src/register/` holds four files: `eigen4.js` (cyclic Jacobi on a symmetric 4 × 4), `fit.js` (closed-form fits on centred Float64 sums, residuals, leave-one-out), `controlPoints.js` (parse and match), `align.js` (picks → `fitTransform`; ICP on a thinned sample of the moving cloud against the 0.7.0 k-d tree of the fixed cloud, normals fitted lazily where the sample lands). Every result is the 0.5.0 `{ m, t }`, world to world.

**Tech Stack:** plain ES modules, `node:test`, no dependencies; the demo uses Three.js (demo only).

**Spec:** `docs/design/2026-10-23-register-0.8.0-design.md`

## Global Constraints

- No dependencies in las-laz-js; no WASM.
- Code style as the repo: `var`, `function` declarations, tabs, a `// src/…` banner block at the top of each new file, JSDoc on every export, `/* prettier-ignore-file */` in tests.
- Errors are `LasError` `ERROR_CODES.INVALID_ARGUMENT` with a message naming the argument (and the pair number or line number where there is one).
- Transforms are `{ m: 9 numbers row-major, t: 3 numbers }`, p' = m·p + t, world to world; check with `checkTransform` (`src/ops/transform.js`) where one is taken in.
- All fitting arithmetic in Float64 on offsets from each set's weighted centroid.
- Models and minimum pairs: `"rigid"` (default) 3, not on one line; `"level"` 2, distinct XY; `"scale"` 3, not on one line. Degenerate: the `from` set's covariance middle eigenvalue ≤ 1e-12 × its trace (rigid / scale); Σ wᵢ (aₓ² + aᵧ²) ≤ 1e-24 × (the set's largest |coordinate offset|)² (level).
- ICP defaults: `iterations` 30, `sample` 50,000, `k` 16; `maxDistance` required (message as 0.7.0's `checkMaxDistance`). Stop when the increment's rotation < 1e-7 rad and its shift < 1e-6 × `maxDistance`. Fewer than the model's minimum pairs in an iteration → stop, keep the last transform, `converged: false` (no throw).
- Control-point names match exactly after trimming, case-sensitive.
- Every new public function is exported from `src/index.js` in the task that writes it.
- Tests are oracles (known transforms, brute-force minimisers, synthetic surfaces), never snapshots.
- `npm test` passes after every task. Coverage after the last task: no metric below lines 99.74, branches 97.22, functions 98.27 (0.7.1).
- Private samples named by id only; `npm run check:private` after staging, before every commit.
- Commits straight on `main`, ending `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`; never push.

## Review Focus

1. **Real scans arrive at UTM magnitude on one side and near 0,0 on the other** (scan frame → mine grid): the fit must not lose precision when `from` is near the origin and `to` is ~6.7 M — recovery within 1e-9 relative, residuals in mm exactly as at the origin. → Task 1 test.
2. **Applying a GCP transform to Float32 local columns in the demo:** the result is ~6.7 M away from the old origin; written straight into Float32 it loses centimetres. Expected: the demo re-bases (Float64 world, new origin at the transformed centre, Float32 local). → Task 6 Step 1 and the Task 7 browser check.
3. **A control file exported from Excel:** a UTF-8 BOM, a trailing empty column (`CP1,478000.1,6772000.2,301.5,`), and numbers with thousands separators are not numbers (refused, line named) — BOM and trailing comma accepted. → Task 3 test.
4. **Two picks on the same feature** (the user clicks the same point twice, or two pairs at one spot): rigid with 3 pairs where two coincide is a line → refused with the degenerate message, not NaN. → Task 1 test.
5. **ICP on clouds that do not overlap** (picks wrong by more than `maxDistance`): `used` 0 at the first iteration → returns the picks' transform, `converged: false`, `rmsBefore` / `rmsAfter` NaN — never throws, never NaN in the transform. → Task 4 test.

**Interfaces:**

- Produces (public): `fitTransform(from, to, { model?, weights? }?) -> { transform, model, scale, rotateZ, residuals, dH, dZ, looResiduals, rms, worst }` as spec §2. In this task: `"rigid"` and `"scale"`; `looResiduals` filled with NaN and `worst` = index of the largest residual (Task 2 fills both properly).
- Produces (internal, for Task 2 and 4): `solve(from, to, w, model, skip) -> { m, t, scale, rotateZ } | null` — the fit without pair `skip` (−1 none); null when degenerate.

- [ ] **Step 1: Write the failing tests** in `test/register/fit.test.js` (helpers: a seeded `rng`; `randomRotation(r)` from a random unit quaternion; `applyT(T, xyz)`):
  - `"rigid recovers a known transform"` — 200 trials, n ∈ {3, 4, 10, 50} random points in a 100 m cube; random rotation and shift; `m` and `t` within 1e-9 of the truth; residuals all < 1e-9; `scale` 1.
  - `"scale recovers rotation, shift and scale"` — scale ∈ [0.5, 2]; within 1e-9.
  - `"UTM magnitude"` — `from` near 0, `to` = truth applied then shifted to (478000, 6772000, 300): `t` within 1e-6 absolute, residuals < 1e-6 m (Review Focus 1).
  - `"noise gives an RMS near sigma"` — n 500, Gaussian σ 0.01 on `to`: rms within [0.8σ, 1.2σ]·√((3n − 6)/(3n)).
  - `"no other rigid transform scores lower"` — 20 noisy cases; perturb the fit's rotation (3 small angles) and shift by ±1e-4 in 50 directions: weighted sum of squares never lower than the fit's (minus 1e-12).
  - `"weights"` — a weight-0 pair moved 5 m does not change `m` / `t` (1e-12) and its residual is still reported; doubling all weights changes nothing.
  - `"dH and dZ"` — for every pair, dH = hypot(rx, ry), dZ = rz, residual = hypot(dH, dZ).
  - `"never a reflection"` — `to` = `from` mirrored in x: det(m) > 0.
  - `"degenerate sets are refused"` — 2 pairs (rigid) → `/at least 3/`; 3 collinear → `/line/`; 3 pairs with two identical points (Review Focus 4) → `/line/`; all coincident → `/line/`.
  - `"bad input is refused, naming it"` — lengths differ → `/from.*to|to.*from/`; length 7 → `/multiple of 3/`; NaN at pair 2 → `/pair 2/`; model "affine" → `/model/`; weights wrong length / negative / all zero → `/weights/`.
  - `"largestEigen4"` — random symmetric 4 × 4 matrices: N·v = λ·v within 1e-10 and λ ≥ every diagonal entry of Vᵀ N V.
- [ ] **Step 2: Run** `node --test test/register/fit.test.js` — Expected: FAIL (module not found).
- [ ] **Step 3: Implement** `largestEigen4` (cyclic Jacobi, sweeps until off-diagonal sum² < 1e-30 × trace², at most 50) and `fitTransform` / `solve` for rigid and scale. Horn's N from S (Sab = Σ wᵢ a'ᵢ_a b'ᵢ_b, a' = from − ā, b' = to − b̄):
  ```
  [ Sxx+Syy+Szz  Syz−Szy      Szx−Sxz      Sxy−Syx     ]
  [ Syz−Szy      Sxx−Syy−Szz  Sxy+Syx      Szx+Sxz     ]
  [ Szx−Sxz      Sxy+Syx     −Sxx+Syy−Szz  Syz+Szy     ]
  [ Sxy−Syx      Szx+Sxz      Syz+Szy     −Sxx−Syy+Szz ]
  ```
  q = (q0, q1, q2, q3) → R (row-major, standard unit-quaternion matrix). Scale: s = Σ wᵢ b'ᵢ·(R a'ᵢ) / Σ wᵢ |a'ᵢ|². t = b̄ − s R ā. Residuals use all pairs. Export `fitTransform` from `src/index.js`.

- [ ] **Step 1: Write the failing tests** in `test/register/align.test.js`. A synthetic bench (helper in the test file): a 60 m × 40 m floor at z 0, a 70° face rising 15 m, a crest, a second floor at z 15, points every 0.1 m with Gaussian noise σ 0.005 m (about 300,000 points); the moving cloud = the same surface resampled with a different seed, moved by a known transform (rotation ≤ 2° about a random axis, shift ≤ 0.5 m):
  - `"picks only equals fitTransform"` — `alignCloud(m, f, { pairs })` with no `icp` → `transform` deep-equals `fitTransform(pairs.from, pairs.to).transform`; `icp` undefined.
  - `"ICP from three sloppy picks reaches the noise"` — picks = three true correspondences (floor, face, crest) with 5 cm errors; `icp: { maxDistance: 0.5 }`: recovered rotation within 0.02°, shift within 5 mm; `converged` true; `rmsAfter` < 2σ; `rmsAfter` < `rmsBefore`.
  - `"60 % overlap still converges"` — moving cloud cropped to 60 % of the surface: same tolerances.
  - `"level ICP stays level"` — `model: "level"`, a truth with no tilt: tilt terms exactly 0.
  - `"scale keeps the picks' scale"` — `model: "scale"`: `fit.scale` and the final transform's scale (cube root of det m) equal within 1e-12.
  - `"origins: local Float32 columns give the same world transform"` — both clouds as Float32 local columns about two different origins (one at UTM): the transform equals the Float64 world run within 1e-6 m on the cloud's extent.
  - `"clouds that do not overlap"` — picks wrong by 50 m, `maxDistance` 0.5: `used` 0, `converged` false, transform = the picks' transform, `rmsBefore` / `rmsAfter` NaN, no NaN in `m` / `t` (Review Focus 5).
  - `"onProgress"` — called with (done, total), the last call (iterations run, iterations run).
  - `"bad options are refused"` — no `pairs` → `/pairs/`; `icp: {}` → `/maxDistance is required/`; `movingOrigin: [1, 2]` → `/movingOrigin/`; `icp.iterations` 0 → `/iterations/`; `icp.sample` 1.5 → `/sample/`.

- [ ] **Step 3: Implement** `alignCloud` per spec §3 (ICP): the sample in world Float64 (local + `movingOrigin`), mapped each iteration by the current world transform, then minus `fixedOrigin`; the tree on the fixed columns once; per pair, the nearest fixed point within `maxDistance` and its normal from `fitAt` (k, maxD2 = `maxDistance`²), cached in a `Map` keyed by fixed point number (null when it has no plane); the 6 × 6 (level: 4 × 4) normal equations on offsets from the matched pairs' centroid, solved by Cholesky with a 1e-12 × trace ridge; the increment applied on the left as an exact rotation (Rodrigues) about that centroid plus the shift, so the model's scale is kept. `rmsBefore` = point-to-plane RMS at the picks' transform, `rmsAfter` = one more correspondence pass at the final transform.
