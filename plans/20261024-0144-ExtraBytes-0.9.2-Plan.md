# Extra Bytes 0.9.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** read every LAS 1.4 Extra Bytes field (types 1–30 and undocumented bytes) into columns, write types 1–10 and raw bytes from columns (LAS and LAZ, both writers), so a file's extra bytes survive a read → save and the facet / joint-set columns can be saved; the demo shows, keeps and saves them.

**Architecture:** `src/format/ExtraBytes.js` owns the 192-byte descriptor: `parseExtraBytes` (file → fields), `layoutExtraBytes` (writer descriptors → checked layout + record length) and `buildExtraBytes` (layout + raw min / max → VLR payload). `decodeRecords` reads fields from a parse result passed as `opts.extraBytes`; `encodeRecords` writes them from a layout; `writeLas.js` carries the record length (format size + extras) through LAS, streaming and LAZ, and adds the VLR to the header it already patches at the end.

**Tech Stack:** plain ES modules, `node:test`, no dependencies; PDAL (QGIS 4.2.3 install) as an outside oracle where present.

**Spec:** `docs/design/2026-10-24-extra-bytes-0.9.2-design.md`

## Global Constraints

- No dependencies; no WASM. Code style as the repo: `var`, `function` declarations, tabs, a `// src/…` banner block on each new file, JSDoc on every export, `/* prettier-ignore-file */` in tests. Bit masks on single bytes (the `options` bits) are marked `// bits-ok` (test/guards.test.js).
- Errors: `LasError` `ERROR_CODES.INVALID_ARGUMENT`, message naming the field (and the point, for a value).
- Descriptor layout (LAS 1.4 R15): `data_type` u8 @2, `options` u8 @3, `name` char[32] @4, `no_data` @40, `min` @64, `max` @88 (8 bytes each: u64 for unsigned, i64 for signed, f64 for floats), `scale` f64 @112, `offset` f64 @136, `description` char[32] @160; 192 bytes. `options` bits: 0 no_data, 1 min, 2 max, 3 scale, 4 offset. Type 0 = undocumented, its byte count in `options`. Types 11–20 = 2 × types 1–10, 21–30 = 3 ×; 31–255 reserved. Array elements j > 0 sit at @40 + 8j, @64 + 8j, … (the R13 layout; R15 calls them deprecated).
- Type names: `"u8" "i8" "u16" "i16" "u32" "i32" "u64" "i64" "f32" "f64"` = codes 1–10; `"raw"` = 0.
- Reserved columns: every `FIELD_TYPES` key plus `count`, `positions`, `bounds`, `stats`, `colours`, `normal`, `extra`, `extraBytes`. A clashing file name reads as `<name>_extra`; a repeat gets `_2`, `_3`.
- Scaled = the descriptor sets scale or offset; scaled columns are `Float64Array` (value = raw × (scale ?? 1) + (offset ?? 0)), raw == noData → NaN. Unscaled keep the stored type; 64-bit as `BigUint64Array` / `BigInt64Array`.
- `noData`, `min`, `max` are raw values everywhere (read and write).
- Default read fields unchanged; writes without `extraBytes` produce the 0.9.1 bytes.
- Tests are oracles (bytes written by test helpers with their own DataView code, values computed in the test, PDAL), never snapshots.
- `npm test` passes after every task. Coverage after the last task: no metric below the figures `npm run test:coverage` gives at the start of Task 1 (ledger them).
- Private samples by id only; `npm run check:private` after staging, before every commit.
- Commits straight on `main`, ending `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`; never push.
- Ruling (spec §2 Writing, "other properties … ignored"): the writer reads `k` only to refuse it — a typed descriptor with `k` > 1 (a deprecated array read from a file) is refused, "… is a 2- / 3-value array type: read, not written; write k scalar fields". The spec line is amended in Task 3.

## Review Focus

1. **A read → save of a LAZ file with extra bytes in point format 7 at UTM coordinates** (the common TLS export): the saved records equal the source's byte for byte, and the saved file reads back with the same `extraBytes` list (names, types, scale, offset, noData). → Task 3 round-trip test over f7x.
2. **Filters and thinning with an extra column** (`classes`, `bounds`, `maxPoints` on a file with a u16 and a scaled i32 field): the extra columns stay aligned with x / y / z point for point. → Task 2 test.
3. **A streaming save in batches whose min / max are set by a later batch:** the VLR's raw min / max cover every batch; a refused batch (value out of range) leaves `totals` and the next batch's position untouched. → Task 3 test.
4. **A scaled field holding NaN with and without `noData`:** with noData, NaN round-trips (written as noData, read as NaN); without, the write is refused naming the field and the point. → Task 3 test.
5. **Edits in the demo after a read with extras** (Remove, Split, Classify, then Save): the saved file carries the edited cloud's extra columns, not the file's. → Task 5 browser check.
