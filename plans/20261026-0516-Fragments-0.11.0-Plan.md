# Fragments 0.11.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `findFragments` (facets merged across convex edges into rock fragments: per-point fragment ids; per fragment axes, sieve-size estimate, area, outline) and `sizeDistribution` (% passing curve, P-values, Swebrec / Rosin–Rammler fit); the demo gains a Fragments tab with an SVG size chart.

**Architecture:** `src/fragments/sizeDistribution.js` is pure statistics on fragment objects; `pileNormals.js` the coarse grid that gives the pile's outward direction; `axes.js` the PCA measure shared by `findFragments` and the test oracle; `findFragments.js` runs `findFacets`, votes on facet contacts, merges by union-find, fills and measures. The demo's tab lives in `examples/browser/fragments.js`, the chart in `sizeChart.js`.

**Tech Stack:** plain ES modules, `node:test`, no dependencies; Three.js in the demo only.

**Spec:** `docs/design/2026-10-25-fragments-0.11.0-design.md`

## Global Constraints

- No dependencies in las-laz-js; no WASM. Never import trimesh-build-js or trimesh-boolean.
- Code style as the repo: `var`, `function` declarations, tabs, a `// src/…` banner block at the top of each new file, JSDoc on every export, `/* prettier-ignore-file */` in tests.
- Errors are `LasError` `ERROR_CODES.INVALID_ARGUMENT` with a message naming the argument.
- `findFragments` defaults: `k` 16; `facetOptions` over `{ maxAngle: 20, minArea: 0, minPoints: 10 }`; `concaveAngle` 10; `surfaceDistance` 10 × `maxDistance`; `fill` true; `fillDistance` `maxDistance`; `minPoints` 50; `maxDistance` required. An edge votes only with ≥ 3 pairs; convex when more than half vote convex. Axes are 2nd–98th percentile spans, longest first; `size` = `axes[1]`. Fragment ids 1 … n by size, largest first (ties: count, then first point index); 0 = none.
- `sizeDistribution` defaults: `weight` `"volume"` ((π/6)·a·b²), `model` `"swebrec"`, `fitFrom` 60, `fines` 0, `percents` [10, 20, 50, 80, 90]. Fit needs ≥ 3 measured points with fitFrom ≤ P < 100. Swebrec xmax by golden section in (largest × (1 + 1e-6), 3 × largest], 60 steps, minimising RMSE in % passing.
- Every new public function is exported from `src/index.js` in the task that writes it: `findFragments`, `sizeDistribution`.
- Tests are oracles (rocks and sizes by construction, hand-computed curves), never snapshots.
- `npm test` passes after every task. Coverage after the last task: no metric below the figures `npm run test:coverage` gives at the start of Task 1 (ledger them).
- Private samples named by id only; `npm run check:private` after staging, before every commit.
- Commits straight on `main`, ending `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`; never push.

## Review Focus

1. **A face nearly edge-on to the pile direction** (|n_facet · pile| < 0.1, e.g. a steep side of a tilted rock): its outward sign is a coin toss, so its votes would split its own rock or bridge two. Expected: edge-on facets do not vote; after the merge each joins the fragment it shares the most contact pairs with (its own fragment when it has none). → Task 4 test.
2. **The bench floor or a wall inside the selection** becomes one huge "fragment" that swamps the volume-weighted curve. Expected: the demo warns when the largest fragment's `area` exceeds 25 % of `surfaceArea`, naming its id, so it can be selected and deleted. → Task 5 browser check.
3. **Dust and stray points in the air:** must stay 0 (the fill reaches only `fillDistance` from a facet point) and never give NaN axes. → Task 4 test.
4. **A curve with too little in it:** one fragment, all sizes equal, or zero spread in the fit range. Expected: `passing` [100], `fit` null, `sizeAt(50)` NaN, no throw. → Task 1 test.
5. **Re-running gives the same answer** (Kirra will re-run on the same scan): two runs on one cloud give identical `fragment` columns and fragment lists. → Task 4 test.

Breadth-first over the 26 neighbours, each flipped to agree with the cell it was reached from. First cell: with `viewpoint`, the cell whose centroid is nearest it, flipped so n · (viewpoint − centroid) > 0; without, the largest |n_z| facing up (ties: lowest cell number).   - Facet outward normal: `poleOf(normal)` flipped so its dot with the normalised sum of its points' pile normals is positive; **edge-on** when |that dot| < 0.1.
  - Contacts: a `Map` keyed `i · (F + 1) + j` (i < j) → { pairs, convex }; each pair found from p counts once (found again from q, it counts again); pairs touching an edge-on facet are counted separately per facet and fragment root, not voted.

  - Median spacing from the first-neighbour distances of the contact pass (the first 4,096), for the outline cell.
