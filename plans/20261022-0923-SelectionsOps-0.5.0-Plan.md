# Selections and column operations 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** zero-dependency operations on point columns (select, keep / remove / split / merge, transform, interleave), plus an `index` column, a transform on read and a polygon crop on read; and the browser demo showing them.

**Architecture:** new `src/ops/` modules work on plain `{ count, <name>: TypedArray }` objects (a column is any typed array of length `count × k`); a selection is an ascending `Uint32Array`. The reader gains three things inside its existing per-record loop (`decodeRecords`) and filter builder (`makeKeep`): an `index` field, a Float64 transform applied before `localOrigin` / Float32, and a polygon test on the raw record. The demo gets an Edit tab that drives the new functions on the cloud in memory.

**Tech Stack:** plain ES modules, `node:test`, no dependencies (the demo keeps its pinned Three.js from a CDN).

**Spec:** `docs/design/2026-10-22-selections-ops-0.5.0-design.md`

## Global Constraints

- No dependencies in las-laz-js: nothing added to `package.json` `dependencies` / `devDependencies`; no WASM.
- Code style as the repo: `var`, `function` declarations, tabs, a `// src/…` banner comment block at the top of each new file, JSDoc on every export, `/* prettier-ignore-file */` in tests.
- Every error is a `LasError` with code `ERROR_CODES.INVALID_ARGUMENT` and a message naming the argument (spec §5).
- Every new public function is exported from `src/index.js` in the task that writes it.
- Tests are oracles (hand-worked values, or an equality with an independent path), never snapshots.
- `npm test` passes after every task (the dedupe 2 M-point timing test is known to be flaky under load; it passes alone).
- Coverage after the last task: no metric below lines 99.61, branches 95.90, functions 97.59 (`npm run test:coverage`).
- Commits go straight on `main`; never push.

## Review Focus

1. **`bounds` with only some limits** (`{ minZ: 100 }`): today's `makeKeep` compares with `undefined` and keeps nothing. A person expects an omitted limit to mean no limit, as `selectBox` does. → Task 2 fixes and tests it.
2. **A polygon given closed** (last vertex repeating the first, as Kirra and most GIS tools store rings): the zero-length closing edge must not mark points as on the boundary or flip the crossing test; the result equals the open ring. → Task 2 test.
3. **A stale selection** (made on a cloud, then applied after points were removed) or a plain JS `Array` from Kirra: an index ≥ count must throw naming its position, a plain array of whole numbers must work. → Task 1 test.
4. **Crop on read together with `maxPoints`**: exactly `maxPoints` of the inside points, the same as `keepPoints(cropped, thinSelection(cropped.count, maxPoints))`. → Task 2 test.
5. **`transform` with `float32` but no `localOrigin`**: today's rule (Float32 only with an origin) must hold, so the transformed columns stay Float64. → Task 5 test.

### Task 1: Columns, selection checks and the simple selections

**Files:**
- Create: `src/ops/columns.js`, `src/ops/select.js`
- Modify: `src/read/decodeRecords.js` (thinning uses `thinStep`), `src/index.js`
- Test: `test/ops/columns.test.js`, `test/ops/select.test.js`

**Interfaces:**
- Produces (`src/ops/columns.js`, internal):
  - `columnsOf(cols) -> Array<{ name: string, k: number }>`: checks `cols.count` is a whole number ≥ 0 (else INVALID_ARGUMENT "count …"); a column is an own property that is a typed array (`ArrayBuffer.isView`, not `DataView`) with `length === count * k`, `k` a whole number ≥ 1; when `count === 0`, every typed array of length 0 is a column with `k = 1`. Other properties (numbers, `bounds`, a typed array of any other length) are skipped silently.
  - `checkSelection(sel, count, name) -> Uint32Array`: accepts a `Uint32Array` or a plain `Array` of whole numbers (checked as given, then copied into a `Uint32Array`); strictly ascending, each `< count`. Message names the first bad position, e.g. `selection[2] = 5 is not above selection[1] = 5`, `selection[3] = 12 is not below count 10`, `selection[0] = 1.5 is not a whole number ≥ 0`. `name` replaces "selection" in the message (set operations pass "a" / "b").
  - `needColumn(cols, name, fn) -> TypedArray`: the k = 1 column or INVALID_ARGUMENT `"<fn> needs a <name> column"`.
- Produces (`src/ops/select.js`, public unless noted):
  - `selectBox(cols, { minX, maxX, minY, maxY, minZ, maxZ }) -> Uint32Array` — inclusive; an omitted (undefined) bound is no limit; needs `x`, `y`; `z` only when `minZ` or `maxZ` is given.
  - `selectClasses(cols, classes: number[]) -> Uint32Array` — `classification` in the list.
  - `selectReturns(cols, { returns, first, last, single }) -> Uint32Array` — `returns`: `returnNumber` in the list (the reader's `returns` filter); `first`: `returnNumber === 1`; `last`: `returnNumber === numberOfReturns`; `single`: `numberOfReturns === 1`. Criteria given combine with OR; none given → INVALID_ARGUMENT. Needs `numberOfReturns` only for `last` / `single`.
  - `thinSelection(count, target) -> Uint32Array` — whole numbers ≥ 0 (else INVALID_ARGUMENT); `target >= count` → every index; else the reader's accumulator rule, exactly `target` indices.
  - `thinStep(thin) -> boolean` (internal, exported for `decodeRecords`): the one place the rule lives:
    ```js
    thin.acc += thin.target;
    if (thin.acc < thin.total) return false;
    thin.acc -= thin.total;
    return true;
    ```
  - `unionSelections(a, b)`, `intersectSelections(a, b)`, `subtractSelections(a, b)` -> `Uint32Array` — linear merges; both checked with `checkSelection(x, Infinity, "a" | "b")`.

**Interfaces:**
- Consumes: `columnsOf`, `needColumn` (Task 1).
- Produces:
  - `makePolygonTest(polygon, { boundary, tolerance }) -> { test(x, y) -> boolean, minX, maxX, minY, maxY }` (internal, `src/ops/polygon.js`): validates (spec §5: array-like of finite numbers, even length, ≥ 6 values; `boundary` `"touching"` default or `"inside"`; `tolerance` finite ≥ 0, default 0); the box is the polygon's, grown by `tolerance`.
  - `selectPolygon(cols, polygon, { boundary, tolerance, minZ, maxZ }) -> Uint32Array` (public).
  - `makeKeep(filter, header)` takes `filter.polygon`, `filter.boundary`, `filter.tolerance` (world coordinates of the file, from the raw record), ANDed with the other filters.

Algorithm for `test(x, y)` (spec §3 — the boundary decision comes first, so an edge point never depends on crossing-test rounding):
```
outside the grown box → false
onEdge = some edge (a → b) has dist2(p, a, b) <= tolerance²
    dist2 = 0 when cross = (bx-ax)(py-ay) - (by-ay)(px-ax) === 0 and p is inside the
    segment's own box; otherwise the squared distance to the clamped projection
    (a zero-length edge: the squared distance to a)
onEdge → boundary === "touching"
else → even-odd crossing test (PNPOLY)
```

### Task 3: Keep, remove, split and merge

**Files:**
- Create: `src/ops/apply.js`
- Modify: `src/ops/columns.js` (`widestType`), `src/index.js`
- Test: `test/ops/apply.test.js`

**Interfaces:**
- Consumes: `columnsOf`, `checkSelection` (Task 1).
- Produces (public):
  - `keepPoints(cols, sel, { inPlace }) -> PointColumns` — `{ count: sel.length, <every column> }` and nothing else.
  - `removePoints(cols, sel, { inPlace }) -> PointColumns`.
  - `inPlace: true`: kept values slide down inside each column's own buffer; the result's columns are `subarray(0, n * k)` views of the input's (same `.buffer`). Default: new columns of the same types.
  - `splitPoints(cols, sel) -> [inside, outside]` — always copies.
  - `mergePoints(list) -> PointColumns & { filled: string[] }` — concatenated in order; column set = union by name in first-appearance order; a column absent from an input is 0 for its points and its name is in `filled` (always an array); `k` differing between inputs → INVALID_ARGUMENT naming the column; `[]` → `{ count: 0, filled: [] }`.
  - `widestType(types: Function[], name) -> Function` (internal): Float64 > Float32 > integer types; among integers the widest; mixed signedness allowed only when the widest is signed and strictly wider than every unsigned one (Uint8 + Int16 → Int16), otherwise INVALID_ARGUMENT naming the column (Int16 + Uint16, Int8 + Uint16). `Uint8ClampedArray` counts as `Uint8Array`. A BigInt array only merges with its own type.

Ruling carried from the spec: spec §3 says "mixed integer types → the wider one"; Int8 + Uint16 → Uint16 would wrap negative values, so that pair throws like the same-width case. Cost if wrong: a caller merging such a pair converts one column first.

### Task 5: Transforms, and the transform on read

**Files:**
- Create: `src/ops/transform.js`
- Modify: `src/read/decodeRecords.js`, `src/LasReader.js` (JSDoc of the read options), `src/index.js`
- Test: `test/ops/transform.test.js`

**Interfaces:**
- Produces:
  - `checkTransform(T, name) -> T` (internal): `T.m` 9 finite numbers, `T.t` 3 finite numbers (arrays or typed arrays), else INVALID_ARGUMENT naming `m` or `t`.
  - `makeTransform({ shift, rotateZ, rotate, scale, about }) -> { m: number[9], t: number[3] }` — `p' = scale · R · (p − about) + about + shift`; so `m = scale · R`, `t = about + shift − m · about`. `rotateZ` degrees anticlockwise about +Z: `R = [c,-s,0, s,c,0, 0,0,1]`, with exact 0 / ±1 for whole multiples of 90°. `rotate` a row-major 3×3 (9 finite numbers). Both given → INVALID_ARGUMENT. `scale` a finite number (default 1); `shift`, `about` 3 finite numbers (default 0).
  - `applyTransform(T, x, y, z, out) -> out` (internal): `out[0..2] = m · p + t` in Float64.
  - `transformPoints(cols, T, { inPlace }) -> PointColumns` — needs `x`, `y`, `z` (k = 1, else INVALID_ARGUMENT "transformPoints needs x, y and z"); computes from the columns' values in Float64, stores into each column's own type; copy by default (new `x`, `y`, `z`; every other column shared by reference); `inPlace` writes into the input.
  - `decodeRecords(…, { transform })`: per kept record, world `(raw · scale + offset)` in Float64 → `applyTransform` → minus `localOrigin` → store (Float32 only when `float32` and `localOrigin`, as today). All three world coordinates are computed when a transform is given, whichever of x / y / z are asked for. Filters still see the raw record (file coordinates). `readPoints` / `chunks` pass `transform` through; `readPoints`' `bounds` are of the output.
