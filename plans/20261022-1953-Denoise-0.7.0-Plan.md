# Denoise 0.7.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `nearestPoints` (k nearest), `selectOutliers` (PDAL's statistical rule), `pointNormals` / `estimateNoise`, and `denoisePoints` (bilateral by default, MLS), on the 0.6.0 voxel index; the demo's Edit tab gains a Denoise section and a Roughness colour mode.

**Architecture:** `src/index/knn.js` adds a k-nearest ring search to the 0.6.0 grid and a "working index" whose cell size comes from sampled k-th-neighbour distances. `src/ops/normals.js` holds the 3 × 3 plane fit (cyclic Jacobi) that `pointNormals`, `estimateNoise` and `denoisePoints` share. `src/ops/outliers.js` and `src/ops/denoise.js` are one loop each over the points, reading neighbours from the working index.

**Tech Stack:** plain ES modules, `node:test`, no dependencies; PDAL 2.10 (`LAS_PDAL`) as a dev-machine oracle only.

**Spec:** `docs/design/2026-10-22-denoise-0.7.0-design.md`

## Global Constraints

- No dependencies in las-laz-js; no WASM.
- Code style as the repo: `var`, `function` declarations, tabs, a `// src/…` banner block at the top of each new file, JSDoc on every export, `/* prettier-ignore-file */` in tests.
- Errors are `LasError` `ERROR_CODES.INVALID_ARGUMENT` with a message naming the argument; above 4,294,967,295 points `TOO_MANY_POINTS` (spec §8). A NaN / infinite coordinate is refused by `buildGrid` (already, naming the point).
- Arithmetic in Float64. Ties between equal distances go to the lowest point number. "Neighbours" = the other points among the k nearest that lie within `maxDistance` (inclusive).
- A selection is an ascending `Uint32Array`.
- Defaults (spec §2): `selectOutliers` k 8, multiplier 2; `pointNormals` / `estimateNoise` / `denoisePoints` k 16; `denoisePoints` method `"bilateral"`, iterations 1; `estimateNoise` samples up to 100,000 points; a point needs ≥ 3 neighbours for a normal and ≥ 5 to move. `maxDistance` required for `pointNormals`, `estimateNoise`, `denoisePoints`; its message includes "e.g. 0.3 m for a handheld scan".
- Every new public function is exported from `src/index.js` in the task that writes it.
- Tests are oracles (brute force, exact planes, synthetic surfaces with a known truth, PDAL), never snapshots.
- `npm test` passes after every task (the dedupe 2 M timing test can be slow under load; it passes alone). Node 24: `node --test` takes quoted globs.
- Coverage after the last task: no metric below lines 99.71, branches 96.91, functions 98.10.
- Private samples named by id only; `npm run check:private` after staging, before every commit.

## Review Focus

1. **Exact duplicate points** (scanners write them): a neighbourhood where every neighbour coincides with the point has no plane — zero normal, NaN residual, the point does not move, no NaN coordinates anywhere. → Task 3 and Task 4 tests.
2. **UTM-magnitude Float64 coordinates** (x ≈ 478 000, y ≈ 6 772 000): fits are computed on offsets q − p, so a plane at UTM gives the same normals (within 1e-9) and moves (within 1e-6 m) as the same plane at the origin. → Task 3 and Task 4 tests.
3. **A region sparser than `maxDistance`** (far from the walk path): points with too few neighbours keep their coordinates exactly; a whole cloud that sparse gives `estimateNoise` NaN and `denoisePoints` returns unmoved coordinates without throwing. → Task 3 and Task 4 tests.
4. **Collinear points** (a scanned blasthole, a scan line): the normal is deterministic, and a straight line of points is unchanged by both methods (heights are all 0). → Task 3 and Task 4 tests.
5. **The edge of a scan** (points with neighbours on one side only): points move along their normal only, so a horizontal noisy patch does not shrink inward — mean |Δxy| < 0.2 · mean |Δz|. → Task 4 test.

**Interfaces:**
- Consumes: `workingIndex`, `knnSearch`, `checkK`, `checkMaxDistance`, `progress` (Task 1); `thinSelection`.
- Produces (public): `pointNormals(cols, { k = 16, maxDistance, onProgress }) -> { normal: Float32Array(3n), residual: Float32Array(n) }`; `estimateNoise(cols, { k = 16, maxDistance }) -> number`.
- Produces (internal, for Task 4):
  - `smallestEigen(m: Float64Array(6), out: Float64Array(4)) -> boolean` — m = [c00, c01, c02, c11, c12, c22] of a symmetric 3 × 3; writes the unit eigenvector of the smallest eigenvalue to out[0..2] and the eigenvalue to out[3], oriented (below); returns false (out = 0, 0, 0, NaN) when the trace is 0.
  - `fitPlane(X, Y, Z, stride, p, nbrs: Uint32Array, m, w: Float64Array | null, out: Float64Array(7)) -> boolean` — covariance of p and its m neighbours about their (weighted) centroid, computed on offsets from p; w[j] the weight of neighbour j (p's own weight 1; null = all 1). out = [nx, ny, nz, residual, cx − px, cy − py, cz − pz]; residual = sqrt(max(0, λmin) / Σw). False when `smallestEigen` is.
  - `orientNormal(out)` — flip so z > 0; if z = 0, so x > 0; if also x = 0, so y > 0.

- [ ] **Step 3: Implement `denoisePoints` in `src/ops/denoise.js`.**
  - `sigma` = the given value, else `estimateNoise(cols, { k, maxDistance })` once (first pass); if it is not > 0, every pass is a copy.
  - Per pass: `workingIndex` over the current coordinates; per point, its neighbours (`knnSearch`, d² ≤ maxD²); fewer than 5, or the farthest at distance 0 → unmoved (and for `normals`, a plain `fitPlane` normal when ≥ 3, else 0).
  - σc = 0.5 × the distance to the farthest neighbour found; σs = 2 · sigma; wc = exp(−t² / 2σc²), wh = exp(−h² / 2σs²).
  - `"bilateral"`: n₀ = plain `fitPlane`; refit with w = wc · wh (h on n₀) → n; δ = Σ w h / Σ w over the neighbours with h and wh on n; p′ = p + n δ.
  - `"mls"`: `fitPlane` with w = wc → n and centroid offset c; p′ = p + n (n · c) (c is the centroid's offset from p, so this is p − n (n · (p − centroid))).
  - Reads the pass's input coordinates, writes a separate buffer of the input's type (`sameType`); pass 2 onwards reads that and writes a second buffer, swapping. The result is built as `transformPoints` builds a copy (new coordinate arrays, other columns shared); `inPlace` copies the final buffer into the input's arrays and returns them.
  - `progress(onProgress, n × iterations)` ticked per point.
