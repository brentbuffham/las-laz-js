# Tiles and level of detail 0.10.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** split a LAS / LAZ file into an additive octree of tiles held in binary scratch (memory, OPFS, a Node folder), built in two streaming passes with bounded memory; pick tiles for a camera within a point budget; load them as point columns; edit them in place; write the edited cloud to LAS / LAZ; reopen a store without rebuilding; drive it all from the Worker and the demo.

**Architecture:** `src/tiles/` holds one module per job. `backends.js` (named blobs on memory / OPFS / Node), `tileFile.js` (a node's bytes), `manifest.js` (A/B manifest, checksum), `octree.js` (pure keys, sampling, chunk octrees), `build.js` (the passes), `select.js` (view selection), `read.js`, `edit.js`, `write.js`, and `TileStore.js`, whose prototype methods call into them. A tile is the source's own LAS records, so `decodeRecords` / `encodeRecords` / `createLasWriter` / the LAZ chunk codec are reused as they are. Octree work runs in raw record integers (the int32 X / Y / Z), so it never meets scale / offset rounding.

**Tech Stack:** plain ES modules, `node:test`, no dependencies; PDAL (QGIS 4.2.3 install) as an outside reader where present.

**Spec:** `docs/design/2026-10-24-tiles-lod-0.10.0-design.md`

## Global Constraints

- No dependencies; no WASM. Code style as the repo: `var`, `function` declarations, tabs, a `// src/…` banner block on each new file, JSDoc on every export, `/* prettier-ignore-file */` in tests, `// bits-ok` on single-byte masks.
- Errors: `LasError` with `INVALID_ARGUMENT` (option named), `UNSUPPORTED`, `ABORTED`, and the new `BAD_STORE` (message names the store and the node).
- Layout version 1. Node file magic `LLZT`. Manifest names `store-a.json` / `store-b.json`. Node files `<key>.<generation>.tile`, key `"D-X-Y-Z"`. OPFS folder `las-tiles/<id>`.
- Defaults: `tilePoints` 50,000; `chunkPoints` 2,000,000; count grid and sampling grid 128 a cube edge; depth limit 20; minimum node edge 100 raw units (100 × the file's scale); `pointBudget` 10,000,000; `minPixels` 100.
- Sampling: per cell of a 128³ grid over the parent's box, the candidate nearest the cell centre (squared distance in raw units); ties go to the earlier candidate in gather order (children by octant 0–7, each child's points in stored order). Octant bits: x = 1, y = 2, z = 4.
- Coordinates on load: record × scale + offset → the store transform (Float64) → minus `localOrigin` → Float32 when `float32` (as `readPoints`).
- Determinism: the same file and options give the same nodes byte for byte whatever `threads` is.
- Tests are oracles (records built by `test/helpers/buildLas.js`, values computed in the test, brute force, PDAL), never snapshots. Private samples by id only (`test/helpers/samples.js`).
- `npm test` passes after every task. Coverage after the last task: no metric below the figures `npm run test:coverage` gives at the start of Task 1 (ledger them).
- `npm run check:private` after staging, before every commit. Commits straight on `main`, ending `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`; never push.
- Ruling (spec §3 Edits, Loading): field names follow `FIELD_TYPES`, not the spec's shorthand. Colour is `red` / `green` / `blue`; the flags are the one `classificationFlags` field (synthetic 1, keyPoint 2, withheld 4, overlap 8); the writable standard fields are `classification`, `classificationFlags`, `intensity`, `userData`, `pointSourceId`, `red`, `green`, `blue`. Task 1 amends the spec.
- Ruling (spec §2 transform): the store holds the transform as `{ m, t }` (`makeTransform`'s form, which `checkTransform` validates and `decodeRecords` applies), not a 4 × 4. Composition `T2 ∘ T1`: m = m2·m1, t = m2·t1 + t2. Task 1 amends the spec.
- Ruling (spec §3 matches): `store.matches(source)` is async (it hashes the source's first 4 KB). Task 1 amends the spec.

## Review Focus

1. **A store from a LAZ file in point format 7 with extra bytes, at UTM coordinates, edited then written as LAZ.** The output reads back with the same `extraBytes` list, the edits applied, and every untouched record byte for byte. → Task 7 test.
2. **The camera inside the cloud with Kirra's orthographic matrix and a `localOrigin`.** `selectTiles` returns the root and the nodes around the camera; no NaN, no throw, and it equals the brute force. → Task 5 test.
3. **A degenerate cloud: 60,000 copies of one point, and a flat cloud with zero Z extent.** The build ends (depth limit, minimum edge), keeps every point, and its cube has a non-zero edge. → Task 3 test.
4. **An edit cut between writing the node and writing the manifest.** On reopen, the store reads exactly as before the edit, and the orphan node file is removed. → Task 6 test.
5. **An empty file (0 points) and a header whose bounds are too small.** The empty file builds to a root of 0 points; `selectTiles` returns the root; write-out gives a valid empty LAS. The small-bounds file keeps every point. → Task 3 test.
