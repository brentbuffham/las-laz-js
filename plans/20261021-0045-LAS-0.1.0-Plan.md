# las-laz-js 0.1.0 (Read + Write LAS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publishable `las-laz-js@0.1.0`: read LAS 1.0–1.4 (point formats 0–10) and write LAS 1.2 / 1.4, streaming files larger than memory, with filters, colouring, a worker and a Three.js demo.

**Architecture:** ecw-js's layout and idioms. Byte sources (memory / Blob / Node file / OPFS scratch) feed pure format decoders; `openLas` reads the header + VLRs, `readPoints` / `chunks` decode record windows into typed-array columns, filters and `colourize` act on columns, `writeLas` encodes columns. A message-protocol worker wraps the reader. Code is ported from Kirra (`KIRRA/src/fileIO/LasFileIO/LASParser.js`, `LASWriter.js`, `src/workers/lasImportWorker.js`, `src/helpers/PointDeduplication.js`) and from ecw-js (`src/io/*`, `src/errors.js`, `src/workers/workerProtocol.js`, `_dev/*`, `.github/workflows/pages.yml`).

**Tech Stack:** Plain ES modules, zero dependencies, Node 22+ (`node --test`), browser (File/Blob, OPFS, module Workers); demo only: Three.js 0.170.0 via import map.

**Spec:** `docs/design/2026-10-21-las-laz-js-design.md` and `docs/design/2026-10-21-las-laz-js-demo-design.md`.

## Global Constraints

- Zero `dependencies` / `devDependencies`; `"type": "module"`; `engines.node ">=22"`; `license "MIT"`; `sideEffects false`; `files ["src", "README.md", "LICENSE", "CHANGELOG.md"]`; exports `"."` → `./src/index.js`, `"./worker"` → `./src/workers/lasWorker.js`.
- ecw-js code style: `var`, `function () {}`, constructor functions with prototypes, tabs, a `//====` header comment per file, JSDoc on exports.
- **Errors (ruling vs spec §3):** one class `LasError(code, message, offset?)` with frozen `ERROR_CODES` — as ecw-js's `EcwError` — not three classes. Codes: `NOT_LAS`, `UNSUPPORTED_VERSION`, `UNSUPPORTED`, `COMPRESSED_LAZ`, `TRUNCATED`, `BAD_HEADER`, `BAD_VLR`, `INVALID_ARGUMENT`, `ABORTED`, `TOO_MANY_POINTS`. Update the spec's Errors paragraph in Task 1.
- Byte positions are Numbers; 64-bit values built as `hi * 2^32 + lo` (`readU64`); never `<<`, `>>`, `>>>`, `|0` on a position or count.
- Coordinates Float64 by default; Float32 only with `localOrigin`.
- Every test value is worked by hand or comes from the ASPRS spec / the file's own header — never from running the code under test.
- Coverage gate (`npm run test:coverage`): lines 97, branches 88, functions 97.
- Private samples live in gitignored `samples/`; `npm run check:private` before every push.

## Review Focus

1. **A `.laz` file opened in 0.1.0** must fail at `readPoints` with `COMPRESSED_LAZ` and a message naming 0.2.0 — not a DataView error (Kirra's current bug). Pinned in Task 7.
2. **A header whose point count disagrees with the file length** (truncated download) must raise `TRUNCATED` naming the offset, never return garbage points. Pinned in Task 7.
3. **LAS 1.4 legacy vs extended counts** (`legacy number of points` = 0 when > 2^32 or format ≥ 6) — read the 64-bit field. Pinned in Task 4.
4. **8-bit colour stored in 16-bit fields** — `colourize` must not darken it. Pinned in Task 8.
5. **A window boundary inside a record** — chunked reads of a file whose record length does not divide the window must decode identically to a whole read. Pinned in Task 7.
