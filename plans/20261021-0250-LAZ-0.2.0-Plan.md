# LAZ read (0.2.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `openLas` / `readPoints` / `chunks` / `readPointsToScratch` read LAZ (LASzip-compressed) point formats 0–3 and 6–8 exactly as they read LAS.

**Architecture:** A port of laz-rs's decoder (arithmetic coder, models, integer decompressor, the v2 point-wise items and v3 layered items) in `src/laz/`. A LAZ file is turned into the SAME raw record bytes a LAS file holds, one chunk at a time, and handed to the existing `decodeRecords` — so filters, thinning, columns, local origin, colour and the memory rules are unchanged and shared.

**Tech Stack:** plain ES modules, no dependencies; `node --test`; PDAL 2.10 (bundled with QGIS 4.2.3) only to MAKE test fixtures, never at run time.

**Spec:** `docs/design/2026-10-21-las-laz-js-design.md` §6 (0.2.0), and the base rules §4.

## Global Constraints

- Zero dependencies; browser + Node 22+; ES modules (spec §1).
- Big-file rules §4: windows, plain-Number positions, typed columns, worker-friendly.
- **Licence (ruling, Brent to confirm):** laz-rs is **Apache-2.0** (relicensed from LGPL in 2022 — NOT MIT, as the spec and the 0.1.0 README said). Ported files live in `src/laz/`, each with an Apache-2.0 header naming laz-rs / LASzip; a `NOTICE` and `LICENSE-APACHE` ship in the package; `package.json` licence becomes `MIT AND Apache-2.0`.
- Release lines and README never quote private sample names (`check:private`).

## Review Focus

1. A chunk table that is missing (offset -1 / 0) — fall back to the copy at the end of the file, else a clear `UNSUPPORTED`, never a hang.
2. The LAST chunk of a fixed-size file holds fewer points than the chunk size.
3. Extra bytes after the standard fields (record length > format size) — the Byte item.
4. Formats 4, 5, 9, 10 (wave packets) and LASzip item version 1 — refused with `UNSUPPORTED`, not garbage.
5. Truncated compressed data — `TRUNCATED`, not an endless decode.

### Task 1: Arithmetic decoder, models, integer decompressor

**Files:** Create `src/laz/ArithmeticDecoder.js`, `src/laz/models.js`, `src/laz/IntegerDecompressor.js`; test helper `test/helpers/lazEncoder.js` (the matching ENCODER + integer compressor, ported from laz-rs `encoders.rs` / `compressors.rs`, test-only); `test/laz/arithmetic.test.js`.

- Round trips through the test encoder: random symbols over 2, 17, 256, 2048-symbol models; bits; `read_bits` 1–32; `read_int`; integer compress/decompress for bits 16 and 32, with contexts, including wrap-around at ±2^31.
- u32 registers in Numbers with `>>> 0`; the coder's interval is named `range` (laz-rs `length`).

### Task 2: LASzip VLR and chunk table

**Files:** `src/laz/LazVlr.js`, `src/laz/chunkTable.js`; tests `test/laz/lazVlr.test.js`.

- `parseLazVlr(bytes)` → `{ compressor, coder, version, chunkSize, items: [{ type, size, version }] }`; `variableChunks` when chunkSize = 0xFFFFFFFF.
- `readChunkTable(source, header, vlr)` → `[{ pointCount, byteCount, start }]`; falls back to the 8 bytes at the end of the file; fixed-size tables fill pointCount and cap the last chunk at the remaining points.

### Task 3: Point-wise v2 items (formats 0–3, extra bytes)

**Files:** `src/laz/v2/point10.js`, `gpstime11.js`, `rgb12.js`, `byte.js`, `src/laz/decompressChunk.js`; fixtures `test/fixtures/laz/` made by `_dev/makeLazFixtures.mjs` (synthetic, seeded, 60,000 points = 2 chunks); `test/laz/pointwise.test.js`.

- Oracle: PDAL's OWN decompression of each fixture (`pdal translate x.laz x.las`), compared record for record, and the seeded builder's values.

### Task 4: Reader wiring

**Files:** `src/LasReader.js`, `src/read/windows.js` (chunk windows), worker, demo; tests in `test/LasReader.test.js`.

- `_scan` reads one or more whole chunks per window, decompresses them into the reused window buffer, then `decodeRecords` as for LAS. `COMPRESSED_LAZ` only for what stays unsupported. `maxPoints`, filters, `localOrigin`, `readPointsToScratch`, worker `chunks` all covered by one LAZ test each.

### Task 5: Layered v3 items (formats 6–8)

**Files:** `src/laz/v3/point14.js`, `rgb14.js`, `nir14.js`, `byte14.js`, layered chunk path; fixtures for 6, 7, 8 (+ extra bytes).

### Task 6: Real files

- Each private LAZ with a LAS twin decodes to exactly the twin's records (spec §6 oracle). A big LAZ checked against PDAL's own decompression where disk allows.
