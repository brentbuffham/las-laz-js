# Categorise 0.7.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `classifyPoints` gives selected points a LAS class without overwriting existing classes unless asked; ASPRS and user class names (64–255) round-trip in the Classification Lookup VLR; the writer refuses classes above 31 in point formats 0–5 instead of masking them; the demo's Edit tab gains a Categorise section.

**Architecture:** `src/ops/classify.js` holds `classifyPoints` and `ASPRS_CLASSES`. `src/format/ClassLookup.js` parses and builds the lookup VLR; the reader exposes it as `las.classNames`, the writer's shared `headerBytes` writes it from `opts.classNames`. The class-range check lives in `encodeRecords`, so `writeLas`, `createLasWriter` and LAZ all get it.

**Tech Stack:** plain ES modules, `node:test`, no dependencies.

**Spec:** `docs/design/2026-10-23-classify-0.7.1-design.md`

## Global Constraints

- No dependencies in las-laz-js; no WASM.
- Code style as the repo: `var`, `function` declarations, tabs, a `// src/…` banner block at the top of each new file, JSDoc on every export, `/* prettier-ignore-file */` in tests.
- Errors are `LasError` `ERROR_CODES.INVALID_ARGUMENT` with a message naming the argument; a malformed lookup VLR is `ERROR_CODES.BAD_VLR`.
- A selection is an ascending `Uint32Array`, checked with `checkSelection(sel, count, name)` (`src/ops/columns.js`); a needed column with `needColumn(cols, name, fn)`.
- **Default protects existing classes:** without options only selected points at class 0 or 1 change. `overwrite: true` changes every selected point. `only: [...]` changes selected points whose class is in the list. `only` with `overwrite: true` is refused.
- Lookup VLR: user ID `LASF_Spec`, record ID 0, entries of 16 bytes `{ uint8 ClassNumber; char Description[15] }`, ASCII, NUL-padded, ascending by code. Names ≤ 15 bytes, printable ASCII (0x20–0x7E).
- Refusal text (exact): `"point N has class C; point formats 0-5 hold classes 0-31 — write point format 6 or higher"`.
- Every new public function is exported from `src/index.js` in the task that writes it.
- Tests are oracles (brute force, bytes built by hand from the spec table), never snapshots.
- `npm test` passes after every task. Coverage after the last task: no metric below lines 99.74, branches 97.20, functions 98.23 (0.7.0 measured 2026-10-23).
- Private samples named by id only; `npm run check:private` after staging, before every commit.
- Commits straight on `main`, ending `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`; never push.

## Review Focus

1. **Existing tests that write classes above 31 in formats 0–5** would now throw — e.g. a fixture writing class 64 to format 3. Expected: such a test is changed to format 6+ or a class ≤ 31, never the check loosened. → Task 3, Step 4.
2. **A lookup VLR written by other software with empty entries** (code set, description all NULs, or all 256 entries present with most blank): `classNames` holds only the entries with a non-empty name. → Task 2 test.
3. **A `Uint8Array` classification that is a view into a shared buffer** (from a `localOrigin` read or `keepPoints` with `inPlace`): copy mode leaves the input untouched; `inPlace` writes through the view only. → Task 1 test.
4. **`createLasWriter` with a bad class in a later chunk:** the error names the point's global number (`first + i`), and the chunks before it stay written. → Task 3 test.
5. **Names with a trailing space or a non-ASCII character (`Bänch`)**: a trailing space is kept on write and trimmed of NULs only on read; non-ASCII is refused with the code named. → Task 2 test.

### Task 1: `classifyPoints` and `ASPRS_CLASSES`

**Files:**
- Create: `src/ops/classify.js`
- Modify: `src/index.js`
- Test: `test/ops/classify.test.js`

**Interfaces:**
- Consumes: `checkSelection`, `needColumn`, `countOf` from `src/ops/columns.js`.
- Produces (public): `classifyPoints(cols, selection, code, { overwrite?, only?, inPlace? }?) -> { columns, changed }`; `ASPRS_CLASSES` (frozen `{ [code]: name }`, codes 0–22, names as spec §2).

- [ ] **Step 1: Write the failing tests** in `test/ops/classify.test.js`, on random clouds (n = 10,000, classes uniform 0–255, a seeded rng as in `test/helpers/clouds.js`) and random ascending selections:
  - `"by default only classes 0 and 1 change"` — result equals a brute loop `if (cls[i] === 0 || cls[i] === 1) cls[i] = code` over the selection; a selected point at class 2 keeps 2; `changed` equals the brute count of points whose class actually changed (a point already at `code` not counted).
  - `"overwrite changes every selected point"` — brute equality; unselected points unchanged.
  - `"only changes the listed classes"` — `only: [7, 18]`, brute equality.
  - `"copy by default, inPlace writes through"` — copy: input `classification` bytes unchanged, every other column `===` the input's; `inPlace`: returned `columns === cols`, the same array object; a `classification` that is a `subarray` view of a larger buffer: copy leaves the buffer unchanged, `inPlace` changes only the view's bytes.
  - `"an empty selection changes nothing"` — `changed` 0.
  - `"ASPRS_CLASSES"` — frozen; keys 0–22; `[2] === "Ground"`, `[7] === "Low point (noise)"`, `[22] === "Temporal exclusion"`.
  - `"bad arguments are refused, naming the argument"` — code −1, 256, 1.5, "2" → `/code/`; `only: [300]` → `/only/`; `only` with `overwrite: true` → `/only.*overwrite|overwrite.*only/`; no classification column → `/classification/`; a descending selection → the 0.5.0 selection message.
- [ ] **Step 2: Run** `node --test test/ops/classify.test.js` — Expected: FAIL (module not found).
- [ ] **Step 3: Implement** `classifyPoints` and `ASPRS_CLASSES` in `src/ops/classify.js`. Build a 256-entry `Uint8Array` "may change" table from the options (default: entries 0 and 1), then one loop over the selection. Copy mode: a shallow copy of the column object with `classification` replaced by `Uint8Array.from` the input. Export both from `src/index.js`.
- [ ] **Step 4: Run** `node --test test/ops/classify.test.js` then `npm test` — Expected: PASS.
- [ ] **Step 5: Commit** `feat(ops): classifyPoints — existing classes kept unless overwrite; ASPRS_CLASSES`.
